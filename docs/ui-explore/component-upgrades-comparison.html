WeMail · 组件升级评估

Before / After · 值得换的组件

挑了我判断最值得更新的 13 块界面，左右对照「当前态 / 升级态」。Agent 面板已按你的意见拆成 Thinking / Tool Chips / Streaming Text 三块。升级态不是抄外部库——是用 WeMail 自己的 token（Paper Postmark Desk）重做，所以你比的是「值不值得换」，而不是「像不像别家」。看完逐个告诉我留不留。

Thinking · 推理轨迹

replaces the reasoning half of agent-activity 推荐替换
当前 / Current推理塞在工具 timeline 里
思考中 3 步推理 · 约 4 秒
推理用户问 Q3 报销合计，得先找 7 月报销邮件再汇总发票。

推理跟工具调用挤在同一条 timeline 里；不看就不知道 agent 怎么得出 ¥4,820。

升级 / Proposed独立 Thinking · 默认折叠
已思考 4 秒
筛主题含「报销」的邮件3 封

默认折叠成「已思考 4 秒」，展开是一条轨迹——用图标区分类型（检索 🔍 / 工具 🔧 / 完成 ✓），推理是纯文字（缩进、更浅），不用文字标签。贴合 Beautiful UI 原版的克制感。

改了什么

  • 独立出来：把推理从工具 timeline 里拆出，单独成 Thinking，不再互相挤。
  • 一条轨迹，图标区分：检索=🔍、工具=🔧、完成=✓，推理是纯文字（缩进、更浅）；不用文字标签，按时间交织在一条轨迹里，不是四个分 tab。
  • 默认折叠：完成后收成一行 quiet chip「已思考 3 步 · 4s」，要审计才展开。

为什么：agent 给的结论（¥4,820）用户想看推导。现在推导藏在工具流里；Thinking 让它独立、可折叠、可审计。

每个工具调用占一整行，6 次迭代最多 6 行；竖向占位大、密度低。

升级 / Proposed折叠成 1 颗摘要 chip
4 次工具调用 · 2 条消息
搜索邮件 读取邮件 准备草稿 查附件…

默认收成一颗「4 次工具调用」摘要 chip；展开是水平 chip，状态用小圆点（跑=珊瑚脉冲、成=绿、败=红）。

改了什么

  • 折叠优先：6 行竖排工具卡 → 1 颗摘要 chip，点开才是水平 chip 列表。
  • 状态小圆点：颜色之外加图形可辨（无障碍），不用整块底色。
  • 跟推理分开：工具是「动作」（02），推理是「思考」（01），各管各的。

为什么：agent 高频核心面，垂直空间贵。6 次工具顶半屏；折叠后常驻一行。

升级 / Proposed内联来源 + 跟进

正文内联角标 [1][2] 指向来源（复用 10·Context Cards 的数据）；底部跟进建议一键继续追问。

改了什么

  • 内联引用：数字处加角标 [1][2]，悬停/点击看来源邮件，复用 Context Cards 的数据。
  • 跟进建议：回答末尾给 2-3 个一键追问 chip，降低继续对话的门槛。
  • 仍是文档面：保留 streamdown 流式正文 + 光标，只加来源层和跟进层。

为什么：agent 回答是最核心产出。现在数字没法核实、聊完就断；加来源 + 跟进，可信度和连续性都上去。

改了什么

  • 正文可读化：font-mono 文本框 → 正文阅读体，像邮件不像代码。

为什么：草稿是 AI 最直接的产出，现在它「看起来像日志」。给它置信度和备选，用户才敢一键采纳。

划词重写

Selection Actions — replaces BubbleToolbar + InlineAiPrompt 推荐替换
当前 / Current格式优先 · AI 一个小星
B I U S
Pistachio holds the top slot all weekend. Churn it first thing Saturday so the batch has time to firm up before the afternoon rush.

AI 只是一颗末尾的小星，用户不知道它能「解释 / 缩短 / 改语气」。

升级 / ProposedAI 意图优先 · 格式收起
AI 解释 改进 缩短 语气 语法 B I
Pistachio holds the top slot all weekend. Churn it first thing Saturday so the batch has time to firm up before the afternoon rush.

把「用 AI 做什么」做成有标签的主操作，格式（B/I）退到末尾。一眼知道能干嘛。

改了什么

  • 意图标签化：解释 / 改进 / 缩短 / 语气 / 语法 直接做成按钮，不再是一颗「猜猜我能干嘛」的星。
  • 格式降权：B / I / U / 链接 / 高亮 收进末尾小簇，主轨留给 AI（这才是划词的高频诉求）。
  • 视觉同源：仍用现有 coral / paper-2 / shadow-3 浮层 token，不引入新色。

为什么：最干净的 1:1 替换。当前 AI 入口太隐蔽，用户感知不到；标签化后「划词 → 改写」成为可见的一步动作。

智能 / 队列状态

Task Rows + timed Loading — replaces IntelligenceStatus + QueueStatusBadge 建议参考
当前 / Current4 颗小药丸
摘要: 完成 标签: 完成 决策: 处理中 草稿: 等待中

只有「完成/处理中」，看不到跑了多久、卡在哪、失败原因。等待期是一片空白。

升级 / Proposed实时行 + 计时 + Loading
正在分析邮件… 3.2s
摘要1.1s完成
标签 · 3 个0.8s完成
回复决策 2.0s处理中

等待期给像素 Loading + 计时；处理中给进度条 + 耗时；失败给重试次数。信息密度高一档。

改了什么

  • 计时：每行带耗时（1.1s / 8.4s），等待焦虑可量化、慢任务可定位。
  • 进度：处理中行加细进度条，失败行显示「重试 1/3」，复用 QueueRunner 的 lease/retry 数据。
  • 等待态：首帧空白 → 珊瑚像素 grid + elapsed 计时，呼应 Paper Postmark 的「一枚邮戳」。

为什么：状态是「系统在替你干活」的反馈。现在反馈太薄，用户不知道该不该等。标「建议参考」是因为收益真实但不是高频痛点。
