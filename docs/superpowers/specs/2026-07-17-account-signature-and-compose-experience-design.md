# WeMail 账号签名与 AI 草稿交互设计

## 背景

当前草稿窗口存在三类问题：

1. 签名配置保存在全局 `wemail.userPreferences` 中，无法按邮箱独立维护；开发环境还残留了 `— Eddie Wang` 测试数据，造成错误身份被插入邮件。
2. 正文编辑器没有清晰传达底部 AI 写作入口，用户必须主动发现并学习操作。
3. 浮动草稿窗口只能拖动和最大化，不能自由缩放；最大化后的恢复行为也不可靠。

本次设计参考 Agentic Inbox 的信息层级和操作路径，复刻其“正文内引导 + 底部 AI 输入”的核心体验，同时保持 WeMail 的品牌色、文案和账号数据，不复制竞品身份或签名。

## 目标

- 每个邮箱独立维护签名，默认开启。
- 默认签名来自真实邮箱身份，不写死任何姓名。
- 签名关闭时，正文不出现签名及 `Sent with WeMail`。
- 将 AI 写作入口直接呈现在空正文中，点击后聚焦底部指令框。
- 浮动草稿窗口支持拖动、八方向缩放、最大化和可靠恢复。
- UI 的结构、间距和交互反馈达到 Agentic Inbox 参考体验的 80% 以上，同时维持 WeMail 品牌辨识度。

## 非目标

- 不修改邮件发送协议或服务端签名拼接逻辑。
- 不自动迁移旧的全局签名内容，避免把污染数据带入账号级配置。
- 不引入新的拖拽缩放依赖。
- 不复制 Agentic Inbox 的品牌名称、账户身份或署名。

## 方案选择

采用账号级本地签名配置与自研窗口矩形状态。

未采用 `react-rnd`，因为现有草稿窗口已有拖动、portal 和最大化逻辑，新依赖会增加事件冲突与包体成本。未采用 CSS 原生 `resize`，因为它只能提供有限的缩放手柄，也无法可靠管理最大化前后的完整窗口状态。

## 账号级签名

### 数据模型

新增版本化的账号级本地存储，例如 `wemail.signaturePreferences.v1`：

```ts
type AccountSignaturePreference = {
  enabled: boolean;
  customText: string;
};

type SignaturePreferenceStore = Record<string, AccountSignaturePreference>;
```

键使用账号 ID，避免同一邮箱重新认证或多账号环境发生串用。找不到账号配置时返回：

```ts
{ enabled: true, customText: "" }
```

旧 `wemail.userPreferences` 内的 `signatureEnabled` 和 `signatureText` 不再参与签名解析，也不迁移到新存储。其他用户偏好仍保留原行为。

### 签名解析优先级

签名启用时，显示内容按以下顺序解析：

1. 非空的账号级 `customText`；
2. 账号 `displayName`；
3. `emailAddress` 的 `@` 前缀；
4. 完整 `emailAddress`，作为异常数据兜底。

解析后的默认块为：

```text
<签名内容>

Sent with WeMail
```

签名关闭时返回空字符串，不保留空白占位，也不显示 `Sent with WeMail`。

### 编辑与发送行为

- 新建、回复、转发时插入当前账号的签名。
- 打开既有草稿时保留草稿正文，不重复插入签名。
- 签名是普通富文本内容，用户可以编辑或整块删除。
- AI 改写只处理签名前的邮件正文，避免未经用户要求更改身份信息；这不限制用户手动编辑签名。
- 用户删除已插入的 `Sent with WeMail` 后，发送前不再强制补回。

### 设置界面

签名设置明确显示当前邮箱账号，并提供：

- 默认开启的“使用邮件签名”开关；
- 当前默认身份预览；
- 可选的自定义签名输入框；
- “恢复默认”操作，清空自定义内容并重新使用展示名称；
- 含 `Sent with WeMail` 的最终效果预览；
- 关闭状态下隐藏签名编辑和品牌尾注预览，并提示“发送邮件时不会添加签名”。

切换账号后立即加载对应账号配置，任何账号的修改不得影响其他邮箱。

## AI 草稿引导 UI

### 正文空态

参考 Agentic Inbox，在正文起始位置显示一行轻量引导：

```text
开始输入或 使用 AI 写作
```

- “开始输入或”使用弱化的中性色。
- “使用 AI 写作”使用 WeMail 强调色并具备可点击、键盘聚焦语义。
- 默认显示占位引导；鼠标悬停到该行或“使用 AI 写作”时，提高文字对比度并展示轻微底色/下划线反馈。
- 用户开始输入真实正文后，引导消失。
- 仅存在自动插入的签名或引用原文时，仍视为“正文为空”，继续显示引导。

### 点击行为

点击“使用 AI 写作”后：

1. 将底部 AI 指令区域滚动到草稿窗口可视范围；
2. 聚焦 AI 输入框；
3. 保持现有正文、签名和选中的写作风格不变；
4. 在输入框仍为空时显示适合邮件回复的示例提示；
5. 焦点环和光标清晰出现，让用户确认操作已经完成。

`ComposeBody` 负责协调正文引导和底部 `AiPromptBar`，通过显式 ref/focus API 完成聚焦，不使用全局 DOM 查询或延时猜测。

### 视觉结构

草稿窗口采用与竞品相近的信息层级：

- 顶部：窗口操作、收件人/发件人/主题与发送按钮；
- 中部：大面积正文区，空态引导紧贴正文起始位置；
- 底部：写作风格、输出语言与圆角 AI 指令输入条；
- 附件和格式化等次要动作保持低视觉权重。

圆角、留白、边框和悬停反馈对齐竞品的克制风格，但发送按钮、AI 强调色、产品尾注使用 WeMail 品牌体系。

## 草稿窗口拖拽与缩放

### 窗口状态

使用单一矩形状态描述窗口：

```ts
type ComposeRect = {
  x: number;
  y: number;
  width: number;
  height: number;
};
```

另保存 `windowMode: "floating" | "maximized"` 和 `restoreRect`。最大化前复制完整矩形到 `restoreRect`；恢复时一次性还原位置与尺寸，避免只恢复坐标或被派生尺寸覆盖。

### 缩放交互

- 提供上、下、左、右及四个角共八个命中区。
- 命中区视觉上尽量隐形，悬停时显示对应缩放光标；右下角可提供极轻的尺寸提示。
- 使用 pointer capture 保证指针移出窗口后仍连续缩放。
- 同时约束最小宽高、视口边界和安全边距。
- 最大化状态禁用拖动与缩放；恢复后重新启用。
- 浏览器/桌面视口变化时，将浮动矩形收敛到新的可视区域内。

### 最大化与恢复

- 浮动状态显示最大化图标，最大化状态显示恢复图标和对应辅助文本。
- 每次点击均切换明确的 `windowMode`，不根据临时尺寸反推状态。
- 恢复到最大化前的精确位置和尺寸；若视口已变小，则在恢复时安全收敛。

## 错误与边界处理

- 账号尚未加载时不插入虚构签名，待账号可用后仅对尚未编辑的新草稿初始化一次。
- `localStorage` 数据损坏时使用默认开启配置，不阻断编辑器。
- 展示名称只包含空格时按未设置处理。
- 邮箱地址异常时保守使用可用的完整字符串。
- AI 输入框不可用时，点击引导不修改正文，并保持可再次操作。
- 快速连续最大化/恢复、拖动或缩放不得产生负尺寸或窗口丢失。

## 测试与验收标准

### 自动化测试

- 签名解析优先级、默认开启、关闭为空和 `Sent with WeMail` 拼接。
- 两个账号的签名配置互不影响，旧全局 `Eddie Wang` 数据不会被读取。
- 新建/回复/转发只初始化一次签名，既有草稿不重复插入。
- 空正文显示 AI 引导，正文输入后隐藏；仅有签名/引用时仍显示。
- 点击“使用 AI 写作”调用底部输入框 focus，并在需要时滚动。
- 八方向缩放的尺寸和坐标计算、最小值与视口约束。
- 最大化保存矩形，恢复后位置和尺寸一致。

### 人工 UI 验收

- 使用至少两个邮箱验证默认签名身份和独立自定义配置。
- 关闭签名后，新建、回复、转发均没有姓名和 `Sent with WeMail`。
- 空正文的 AI 引导在默认、hover、focus 三种状态下清晰且不过度抢眼。
- 点击 AI 写作后无需再次点击即可直接输入指令。
- 从四边和四角均可平滑缩放；最大化和恢复连续执行三次仍正确。
- 在常见桌面尺寸下与 Agentic Inbox 截图并排评估：核心结构与操作路径相似度不低于 80%，视觉完成度不低于 80%，且不存在 Agentic Inbox 身份或品牌内容。

## 完成定义

只有在类型检查、客户端构建、相关单元/组件测试和桌面端实际操作验收全部通过后，才视为完成。验收报告需要列出与 Agentic Inbox 的逐项对照、截图证据、已知差异及评分依据。
