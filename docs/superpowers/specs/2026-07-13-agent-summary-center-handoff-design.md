# AI 面板与摘要中心任务入口设计

## 状态

- 状态：已确认方向 A，待用户审阅设计稿
- 日期：2026-07-13
- 范围：AI 面板空状态、摘要中心入口、Agent 快捷建议

## 背景

竞品的 AI 空状态不是静态欢迎语，而是一个任务启动器。它根据当前邮箱状态，直接给出时间范围明确、结果可预期的操作，例如总结最近邮件、列出本周重点邮件、草拟周报。

当前 WeMail 已有两套能力：

- AI 面板可以通过 `/api/agent/suggestions` 展示建议词并启动对话。
- 摘要中心可以处理批量摘要、摘要失败重试、摘要历史和摘要设置。

目前两者在界面上相互独立：AI 面板使用通用的 `Review inbox` / `Search mail`，邮件列表另有摘要横幅。用户需要自己判断该进入哪个入口，且建议词没有反映当前摘要状态。

## 目标

1. 让 AI 面板成为邮箱任务的第一启动入口。
2. 让摘要中心成为批量摘要任务的权威执行和结果查看入口。
3. 根据摘要状态动态展示最多三个中文快捷建议。
4. 点击摘要类建议时进入明确的摘要中心任务，而不是让 Agent 通过自由文本猜测意图。
5. 保留 Agent 对搜索、重点邮件排序和周报草稿等开放式任务的优势。

## 非目标

- 不把摘要中心重做成聊天界面。
- 不让 Agent 重复实现批量摘要、失败重试和摘要历史。
- 不在本次设计中改变摘要生成算法、摘要数据模型或邮件列表布局。
- 不因为建议词点击而自动发送邮件或执行不可逆操作。

## 产品定位

采用方案 A：

- **AI 面板：发现和发起任务**。负责把邮箱状态翻译成用户可以直接点击的下一步，并承接需要搜索、排序、综合判断的任务。
- **摘要中心：结构化执行任务**。负责批量摘要、失败重试、摘要历史、摘要设置和结果管理。

两者通过带类型的快捷建议连接。摘要类建议直接导航到摘要中心；开放式任务进入 Agent 对话；写作任务进入草稿预览流程。

## AI 空状态

### 结构

```text
Hi，{displayName}

{根据当前状态生成的一句上下文说明}

[建议 1]
[建议 2]
[建议 3]

搜索、写作或询问任何内容
```

建议词最多三个，使用中文，保持现有轻量胶囊样式。AI 面板中的摘要建议与列表摘要横幅可以同时存在，但不能重复显示相同文案；横幅负责持续提醒，AI 建议负责启动动作。

### 建议状态矩阵

| 状态 | 首选建议 | 次选建议 |
| --- | --- | --- |
| 有待处理摘要 | `打开摘要中心，处理 {N} 封待摘要邮件` | `总结最近 24 小时的邮件` |
| 有失败、缺失或无效摘要 | `重试 {N} 封失败摘要` | `查看需要关注的摘要` |
| 已有最新摘要且无待处理项 | `查看本周摘要` | `列出本周最需要处理的 5 封邮件` |
| 没有可摘要邮件 | `列出本周最需要处理的 5 封邮件` | `搜索邮件` |
| 未配置 AI 模型 | `配置摘要模型` | `查看未读邮件` |

第三个建议可以根据账户状态补充：

- `根据本周工作邮件草拟一份周报`
- `查看未完成的邮件待办`
- `搜索邮件`

建议排序应优先体现用户当前最明确的待办，不能固定返回一组与数据无关的按钮。

## 快捷建议动作协议

现有建议返回 `id`、`label`、`prompt`。设计上扩展为可选的结构化动作：

```ts
type AgentSuggestionAction =
  | {
      type: "open_digest_center";
      filter?: "pending" | "attention" | "history";
    }
  | {
      type: "agent_prompt";
      prompt: string;
    }
  | {
      type: "open_compose";
      purpose: "weekly_report";
    };
```

兼容策略：保留 `prompt`，旧客户端仍可发送文本；新客户端优先执行 `action`。

动作行为：

- `open_digest_center`：跳转 `/digests`，并带上摘要任务筛选条件。
- `agent_prompt`：进入 Agent 对话，执行搜索、排序或综合分析。
- `open_compose`：先生成周报草稿预览，用户确认后再进入写信流程，禁止自动发送。

## 摘要中心联动

摘要中心增加可被外部入口使用的深链接参数，例如：

- `/digests?tab=tasks&filter=pending`
- `/digests?tab=tasks&filter=attention`
- `/digests?tab=history`

进入摘要中心后：

1. 自动选中对应页签和过滤条件。
2. 显示与建议词一致的任务上下文。
3. 用户完成批量生成或重试后，返回列表时刷新摘要状态和 AI 建议。

摘要中心仍是批量任务的唯一执行层，AI 面板不直接拼接批量摘要 API 调用。

## 数据流和组件边界

### 数据来源

- `MailDigestStatus`：可摘要邮件数量、时间窗口、最近摘要状态。
- `SummaryHealthStatus`：失败、缺失、无效、待处理和运行中数量。
- 当前账户和当前文件夹范围。
- 当前聚焦邮件的 Agent intelligence context。

### 推荐边界

- `SuggestionBuilder`：负责根据结构化状态生成候选建议和排序，不负责 UI 导航。
- `agentRoutes`：返回建议及可选 action，保持账户隔离。
- `AgentPanel`：渲染建议并执行 action，不复制摘要业务规则。
- `MailDigestBanner`：继续负责列表内摘要提醒，与 AI 面板共享同一状态来源。
- `SummaryCenterPage`：解析深链接并负责摘要任务操作。

## 异常和降级

- 摘要状态加载中：显示骨架或不显示动态建议，不展示错误数量。
- 摘要接口失败：退化到 `列出本周最需要处理的 5 封邮件`、`搜索邮件` 等 Agent 建议。
- 未配置模型：优先引导设置，不发送会失败的摘要命令。
- action 缺失或客户端不识别：使用兼容的 `prompt`。
- 用户点击建议后重复点击：进入发送中状态，避免重复创建任务。

## 测试要求

### 后端

- 为每种摘要状态生成正确的建议顺序。
- 建议包含正确数量时，文案和 action 的数量一致。
- 账户之间不能读取或混用摘要状态。
- 旧客户端仍能使用 `prompt`。

### 前端

- 空状态显示中文动态建议。
- 点击摘要建议能进入对应摘要中心筛选页。
- 点击 Agent 建议能发送正确 prompt。
- 摘要状态变化后建议刷新，避免显示过期数量。
- loading、错误、未配置模型状态都有稳定降级表现。

## 分阶段交付

### Phase 1：建议词和摘要入口

- 替换英文默认建议词。
- 接入摘要状态和摘要健康度。
- 增加结构化 `open_digest_center` action。
- 支持摘要中心深链接。

### Phase 2：Agent 任务建议

- 增加本周重点邮件排序建议。
- 增加未完成待办建议。
- 将 Agent 结果中的邮件引用和打开邮件动作统一到现有展示组件。

### Phase 3：周报草稿

- 汇总本周工作邮件。
- 生成可编辑周报草稿。
- 用户确认后进入写信流程，不自动发送。

## 验收标准

1. AI 面板首次打开时不再显示固定英文 `Review inbox` / `Search mail`。
2. 用户能从 AI 面板一键进入待处理或失败摘要列表。
3. 摘要数量、失败数量与摘要中心实际数据一致。
4. Agent 开放式建议仍能正常搜索和排序邮件。
5. 周报动作不会绕过草稿确认直接发送邮件。
6. 摘要中心和 AI 面板不会出现相互矛盾的状态或过期数量。
