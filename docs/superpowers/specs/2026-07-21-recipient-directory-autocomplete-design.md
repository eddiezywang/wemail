# WeMail 收件人企业通讯录检索与标签输入设计

## 背景

当前写信窗口将收件人保存为逗号分隔文本，并在用户输入时只查询本地企业通讯录快照。该链路有两个已确认的问题：

1. 本地全量同步遍历了 1884 个部门，但 `oab:listEx` 对代码拼装的部门 DN 返回 `FA_FORBIDDEN` 或空结果，最终以 `directory-empty` 失败，联系人表为空。
2. 同一账号使用 Coremail `oab:autoMatch` 搜索 `evan` 可以正常返回 6 位候选，说明登录凭据和远端模糊检索能力可用，故写信检索不应依赖失败的全量同步。

现有输入框还缺少收件人标签、去重、删除和明确的候选选择状态。其 placeholder 与左侧“收件人”标签重复，也不符合成熟邮箱应用的简洁输入体验。

## 目标

- 账号登录或恢复后在后台预热 Coremail Web 登录态，使第一次收件人检索无需重新完成完整登录流程。
- 用户停止输入 300 毫秒后自动搜索姓名、英文名或邮箱；中文输入法组词期间不触发检索。
- 搜索 `evan` 时显示 Coremail 返回的匹配候选。
- 点击候选后生成独立、可删除的收件人标签。
- 收件人、抄送和密送使用一致的标签输入交互，并保持现有草稿、回复、转发和 AI 填充兼容。
- 支持直接输入外部邮箱，不要求其存在于企业通讯录。
- 将远端命中的联系人增量写入本地索引，远端暂时不可用时可回退到已有缓存。
- 不为收件人输入框设置视觉 placeholder；通过行标签、标签内容和候选面板表达状态。

## 非目标

- 本次不逆向或修复 Coremail 全量组织通讯录浏览协议。
- 本次不保证离线浏览全部部门和全部员工。
- 不把 Coremail `sid`、Cookie 或邮箱密码发送给渲染进程。
- 不持久化 Coremail Web 会话；应用重启后重新预热。
- 不改变邮件发送接口对收件人字符串的现有契约。

## 方案选择

采用“远端模糊检索为主、本地增量缓存兜底”的混合方案。

### 备选方案一：仅使用远端检索

实现最简单，也能直接解决 `evan`，但每次查询都依赖网络和 Coremail 服务。会话或网络短暂异常时完全没有候选结果，因此不采用。

### 备选方案二：继续修复全量同步

理论上可以提供完整离线通讯录，但当前部署对批量枚举接口存在权限或协议差异。继续逆向会扩大任务范围，并让写信功能继续受 1884 个部门的长耗时扫描影响，因此不作为本次前置条件。

### 选定方案：远端检索加增量缓存

服务端复用已预热的 Coremail Web 会话调用 `oab:autoMatch`，同时读取本地索引，按邮箱合并去重。远端结果写入本地缓存后，后续相同或相近查询可以本地命中；远端不可用时仍返回已有缓存。

## Coremail 会话生命周期

`DirectoryService` 为当前账号复用一个 `CoremailWebClient`：

- 账号登录或应用恢复已有账号时，后台调用公开的会话预热方法，仅完成 Coremail Web 登录，不执行全量部门扫描。
- 渲染端不额外发起预热请求，避免占用与联系人检索共享的 Chromium 同源连接槽；首次未命中缓存的搜索会复用或等待后端正在进行的登录。
- 桌面端联系人检索通过专用 IPC 调用本地 `DirectoryService`，绕过页面启动阶段十多个 HTTP 请求造成的 Chromium 同源连接池排队；纯 Web 环境保留 `/api/directory/contacts` 回退。
- 客户端把 `sid` 和 Cookie 仅保存在进程内存中。
- 多个并发请求共用同一个登录 Promise，避免重复登录。
- Coremail 返回 `FA_INVALID_SESSION` 时，清除旧 `sid`，重新登录并重试一次。
- 账号退出、切换或密码更新时清除对应客户端实例，后续请求使用新凭据创建会话。
- 会话、密码和 Cookie 不进入应用日志、接口响应或本地联系人数据库。

预热失败不阻塞写信窗口。首次实际搜索仍可重新尝试登录，并在失败时回退本地缓存。

## 检索与缓存数据流

收件人输入的当前查询词发生变化后，前端取消上一计时器并等待 300 毫秒。中文输入法仍处于 composition 状态时不启动计时；组词结束后再按最终文本计时。查询词仍相同且非空时发起搜索：

1. 服务端先查询本地 FTS 索引。
2. 本地已有候选时立即返回，避免让用户等待 Coremail；同时在后台发起去重的远端刷新。
3. 本地没有候选时，服务端使用复用的 Coremail 会话调用 `oab:autoMatch` 并等待结果。
4. 将 `true_name`、`nick_name`、邮箱、别名、拼音、部门和职务规范化为统一联系人结构。
5. 远端与本地结果按小写邮箱去重；前缀匹配优先于普通包含匹配。
6. 将远端命中联系人事务性 upsert 到联系人表和 FTS 索引，返回最多 8 位候选。

相同账号和查询词的后台刷新共用同一个进行中请求，并设置短时刷新间隔，避免用户反复聚焦或输入相同内容时持续请求 Coremail。

前端使用递增请求序号忽略过期响应，避免较早的慢请求覆盖较新的查询结果。查询中允许出现 `@`，从而支持按完整或部分邮箱搜索。

自动启动流程不再触发当前失败的全量部门同步。显式的全量刷新能力保留为后续独立修复项，不影响写信检索。

## 收件人标签输入

### 基本结构

收件人行由三部分组成：

- 左侧固定行标签，例如“收件人”“抄送”“密送”；
- 已选择联系人的标签列表；
- 标签之后的无边框文本输入区。

文本输入区不设置 placeholder，但必须设置对应的 `aria-label`。已有收件人字符串在打开草稿、回复、转发或接受 AI 生成结果时解析为标签；对无法解析的旧值进行保守保留，不丢失用户数据。

### 搜索行为

- 输入非空文本后等待 300 毫秒再搜索；中文输入法组词期间暂停计时。
- 等待期间不显示过早的“无结果”状态。
- 请求进行中在输入区末尾显示轻量加载指示。
- 返回结果后在输入行下方显示候选面板，候选包含姓名、邮箱，以及部门或职务。
- 点击候选即添加标签、清空当前查询并关闭候选面板。
- 上下方向键切换高亮项，Enter 选择，Escape 关闭面板。
- 点击输入区域外部关闭候选面板，但保留尚未提交的查询文本。

### 标签行为

- 标签显示联系人姓名；姓名不可用时显示邮箱。
- 标签可通过末尾删除按钮移除。
- 输入为空时按 Backspace 删除最后一个标签。
- 邮箱比较不区分大小写，同一邮箱不得重复添加。
- 底层仍把标签序列化为现有的 `Name <email>` 或纯邮箱格式，并以逗号连接，保持 `useComposeForm` 和发送接口兼容。

### 外部邮箱与粘贴

- 当当前文本是合法邮箱时，按 Enter、Tab 或逗号可直接生成邮箱标签，无需通讯录命中。
- 粘贴多个逗号或分号分隔的邮箱时逐个解析、去重并生成标签。
- 非邮箱自由文本不能在没有选择候选的情况下变成收件人，避免把英文名误当作可发送地址。

## 错误与边界处理

- 远端搜索失败时返回本地缓存结果，不弹出打断写信的 toast。
- 远端失败且本地也没有结果时，在候选面板内提示“企业通讯录暂时不可用，可直接输入邮箱”。
- 正常完成搜索但没有匹配时显示“未找到联系人”。
- 快速输入、删除或切换收件人/抄送/密送时，旧请求不得改变当前面板。
- 点击候选与输入框失焦之间不得发生竞态；候选选择优先完成。
- 已有草稿中的重复地址在展示时去重，但序列化时不得丢失第一个有效名称。
- 预热失败、会话过期和一次重登失败均不得阻塞草稿保存或手工输入邮箱。

## 测试与验收标准

### 服务端测试

- Coremail 会话预热只登录一次，并被后续 `autoMatch` 复用。
- 并发预热共用登录流程；`FA_INVALID_SESSION` 只自动重试一次。
- 账号或密码变化会丢弃旧客户端。
- 搜索 `evan` 能规范化英文名候选，并按邮箱合并本地与远端结果。
- 远端结果正确 upsert 到联系人表和 FTS；后续本地查询可以命中。
- 远端异常时返回本地缓存，不泄露凭据或会话数据。
- 自动初始化不再启动全量部门扫描。

### 渲染端测试

- 输入后 299 毫秒不发请求，达到 300 毫秒后发起一次搜索。
- composition 开始后即使超过 300 毫秒也不搜索，composition 结束后才按最终文本触发计时。
- 查询改变会取消旧计时器，过期响应不会覆盖新结果。
- 候选面板展示姓名、邮箱和部门，点击后生成标签。
- 标签可删除、按邮箱去重，空输入时 Backspace 删除最后一项。
- Enter、Tab、逗号和批量粘贴可添加合法外部邮箱。
- 非邮箱英文文本不会绕过候选选择直接生成地址。
- 收件人、抄送、密送输入区均没有 placeholder，并具有可访问名称。
- 既有草稿、回复、转发和 AI 应用结果可以正确还原为标签。

### 完成定义

- 聚焦的服务端和渲染端测试通过。
- `npm run typecheck`、`npm run test:server`、`npm run test:renderer` 和桌面构建通过。
- 使用 `evan` 进行真实 Coremail 检索，300 毫秒静默期后开始检索，点击候选后生成可删除标签。
- 桌面端即使仍在加载邮箱列表、标签、设置和 Agent 数据，通讯录候选也不得被渲染器 HTTP 连接池阻塞。
- 使用桌面启动脚本重建并重启应用，renderer 返回 HTTP 200，`startup.log` 同时包含 `loadURL-done` 与 `ready`，且桌面窗口可见。
