# 写信通讯录本地拼音检索与输入反馈优化设计

## 背景

WeMail 的企业通讯录搜索当前采用本地 SQLite 优先、Coremail Web 远端补充的结构，但本地数据只在 Coremail 返回 `fullPY` 时才具备拼音检索能力。实际 `oab:autoMatch` 接口能够用 `xuwei` 等拼音查询联系人，却不会在响应中返回 `fullPY`。现有实现把远端结果写入本地后，又按原查询词重新搜索本地索引，因此会把 Coremail 已经命中的结果过滤掉。

写信界面还有两处视觉反馈需要统一：收件人区域的默认下划线过浅，主题输入框没有同类下划线及聚焦色。设置页同时存在不准确的“源自 Cloudflare 开源项目”产品文案。

## 目标

- 本地通讯录独立支持中文姓名、无声调全拼和每个拼音音节的首字母检索。
- `徐伟` 至少能被 `徐伟`、`xuwei`、`xu wei` 和 `xw` 命中。
- 本地命中时不等待 Coremail；本地无结果时保留 Coremail Web 远端兜底。
- 远端兜底结果当次即可显示，并写入本地供后续搜索。
- 收件人、抄送、密送和主题使用一致、清晰但克制的下划线聚焦反馈。
- 收件人和主题不显示 placeholder。
- 设置页删除 Cloudflare 来源说明，仅保留 Apache 2.0 许可信息。

## 非目标

- 不实现拼音输入纠错、模糊音或声调搜索。
- 不改变收件人标签、外部邮箱、批量粘贴、中文输入法或发送校验规则。
- 不重新设计整套企业通讯录全量同步协议。
- 不删除源码版权头、LICENSE 或合法的第三方许可记录；本次只删除设置页中不准确的产品来源描述。

## 方案选择

采用“联系人写入时生成并持久化拼音索引”的方案，引入 `pinyin-pro` 作为服务端拼音转换依赖。

未采用以下方案：

- 查询时扫描联系人并临时转拼音：无需迁移，但搜索成本随通讯录规模线性增长。
- 只依赖 Coremail 拼音查询并缓存命中词：改动较小，但断网时本地通讯录仍不具备完整拼音能力。

## 拼音索引生成

新增一个职责单一的目录拼音模块，输入联系人显示名称，输出规范化搜索字段：

- 从显示名称中提取连续中文片段。`colinxu(徐伟)` 的英文部分仍由现有姓名和邮箱索引处理，中文片段 `徐伟` 用于生成拼音。
- 使用无声调、小写拼音，并启用姓名开头的姓氏识别。
- 全拼同时生成连写与分词形式，例如 `xuwei` 和 `xu wei`。
- 首字母取每个拼音音节的首字符，而不是只取声母，例如 `王安` 生成 `wa`。
- 多个中文片段分别生成搜索词并去重。
- 若 Coremail 偶尔返回 `fullPY`，将其作为额外搜索词保留，但本地生成结果是基础能力，不依赖该字段。

拼音模块不负责数据库或网络调用，便于单独测试姓名、多音姓氏和中英文混合名称。

## 数据模型与升级

现有 `directory_contacts.full_pinyin` 保存本地生成的连写全拼。新增：

- `pinyin_initials TEXT NOT NULL DEFAULT ''`：保存首字母串。
- `pinyin_index_version INTEGER NOT NULL DEFAULT 0`：标记联系人是否已使用当前算法建立索引。

数据库迁移后，目录服务初始化时先在本地批量处理 `pinyin_index_version` 低于当前版本的已有联系人，再尝试预热 Coremail 登录态。拼音补建不依赖网络；即使登录预热失败，本地联系人也必须已经可按拼音搜索。

1. 根据姓名生成全拼和首字母。
2. 更新联系人行并将版本设为当前值；没有中文片段的联系人也会标记完成，避免每次启动重复扫描。
3. 重新写入对应 FTS 行，保留姓名、邮箱、别名、部门和职位等现有检索字段。

全量同步和远端增量写入均经过同一拼音增强函数，新联系人直接以当前索引版本落库。未来若拼音规则变化，可提高版本并复用同一补建流程。

### Coremail 全量同步兼容性

当前 Coremail 部署会在 `oab:listEx` 请求包含 `@duty` 或 `fullPY` 时对整个部门返回 `FA_FORBIDDEN`。全量同步只请求该部署允许读取的字段：职位使用 `duty`，不再请求 `@duty` 和 `fullPY`。本地拼音模块替代 `fullPY`，因此无需牺牲拼音检索能力。其他真正无权限的部门仍按现有规则跳过，但单个受限属性不能再导致所有部门联系人都被误判为不可读。

## 本地搜索

`directory_contacts_fts.search_text` 包含：

- 姓名、邮箱和邮箱别名；
- Coremail 英文名或昵称；
- 全拼连写和分词形式；
- 拼音首字母；
- 部门路径和职位。

现有短查询兼容逻辑继续保留：少于 3 个字符的 `xw` 使用参数化 `LIKE`，并把 `pinyin_initials` 纳入可搜索字段；3 个及以上字符继续使用 trigram FTS，因此 `xuwei` 和 `xuw` 均可走本地索引。

结果继续按现有本地相关性和姓名排序，数量上限由调用方传入。数据库查询保持参数化，不拼接用户输入。

## 本地优先与远端兜底

搜索流程调整为：

1. 对去除首尾空白后的查询执行本地搜索。
2. 本地有结果时立即返回，不发起 Coremail 搜索，也不让稍后的远端结果改变当前候选顺序。
3. 本地无结果时调用已预热登录态的 Coremail `autoMatch`。
4. 规范化并按邮箱去重远端联系人，为其生成本地拼音字段，同时把本次远端命中的原查询词加入增量搜索词。
5. 将联系人写入 SQLite，并直接把规范化后的远端结果返回给当前下拉框，不再依赖一次可能丢失结果的二次本地过滤。
6. 相同查询再次发生时，应由本地索引直接命中。

远端请求失败时返回空联系人并标记 `remoteAvailable: false`。失败不会删除或覆盖本地快照。相同查询的并发远端请求共享同一个“规范化结果” Promise，使每个等待方都能收到同一批联系人；前端的取消信号和请求编号继续阻止旧查询覆盖新查询。

## 写信界面交互

### 输入线条

- 收件人、抄送和密送控件默认使用 1px `border-edge`（`#e7e5e4`），替换当前过浅的 `border-edge-3`（`#f5f5f4`）。
- 控件内部输入获得焦点时，容器下划线使用 `border-coral`。
- 主题输入框增加同样的 1px `border-edge` 下划线；鼠标或键盘聚焦时切换为 `border-coral`。
- 保留短时边框颜色过渡，不增加完整四周边框。
- 收件人和主题均不设置 placeholder，继续通过可见行标签和 `aria-label` 提供名称。

### 候选列表兼容性

- 保持 300ms 输入停顿后发起搜索。
- 本地命中时直接展示候选；本地为空并等待 Coremail 时继续展示现有加载状态。
- 查询变化时中止旧请求，并通过请求编号忽略迟到响应。
- 候选按邮箱去重，保持鼠标点击、上下方向键、Enter 和 Tab 选择行为。
- 选择后仍生成可删除标签、清空查询并将焦点返回输入框。
- 中文输入法 composition 期间不发起搜索。

## 设置页文案

删除设置页关于区域中的以下可见段落：

> 本应用源自 Cloudflare 开源项目，当前品牌与桌面产品名为 WeMail。

保留带图标的“许可：Apache 2.0”信息，不新增替代宣传语。

## 错误处理

- 拼音生成只处理字符串并返回空数组作为无中文结果，不应阻断联系人写入。
- 单条异常联系人不应使整批通讯录同步失败；无有效邮箱的记录继续按现有规则跳过。
- 旧数据补建采用事务更新联系人及其 FTS 行，避免字段和索引不一致。
- Coremail 登录或查询失败沿用目录服务的结构化错误码和日志，不在日志中记录查询正文或邮箱凭据。

## 测试

### 服务端单元测试

- 拼音模块：`徐伟 → xuwei / xu wei / xw`、`王安 → wangan / wa`、中英文混合名称、多音姓氏、无中文名称和重复片段。
- Repository：中文、全拼、全拼前缀、首字母、英文名、邮箱和别名均可检索。
- 数据迁移与补建：旧联系人升级后生成字段、更新版本并重建 FTS；无中文联系人不会在后续启动重复补建。
- DirectoryService：本地命中不调用远端；本地为空时调用远端；远端结果当次返回、去重并持久化；后续相同拼音本地命中；远端失败保持安全回退。

### 前端组件测试

- 300ms 防抖、输入法保护、旧请求取消和迟到结果忽略继续通过。
- 点击、方向键、Enter/Tab 选择和标签删除继续通过。
- 收件人控件包含 `border-edge` 与 `focus-within:border-coral`。
- 主题输入框没有 placeholder，包含默认下划线和聚焦珊瑚色样式。
- 设置页不再渲染 Cloudflare 来源说明，仍显示 Apache 2.0 许可。

### 构建与人工验收

- 执行 WeMail Windows 快速桌面构建并重启应用。
- 实际输入 `xuwei` 和 `xw`，确认本地联系人快速出现，可点击生成标签。
- 聚焦收件人与主题时确认下划线由浅灰变为珊瑚色。
- 打开设置页，确认只显示 Apache 2.0 许可，不再显示 Cloudflare 来源说明。
