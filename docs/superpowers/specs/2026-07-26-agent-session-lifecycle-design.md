# WeMail AI 会话生命周期设计

## 目标

WeMail 启动、重启以及从邮件详情返回首页时，右侧 AI 面板都应呈现一个全新的空会话。只有用户主动打开邮件详情或主动选择历史会话时，才恢复已有上下文。

会话历史继续保存在服务端。本设计只改变客户端自动选择哪个会话，不删除历史数据。

## 会话模式

客户端显式维护三种互斥模式：

- `home-fresh`：首页新会话。每次进入该模式都生成新的会话 ID，不读取上一轮首页会话。
- `email-trace`：邮件追溯会话。用户打开邮件详情时进入，以邮件 ID 关联相应会话并加载其历史。
- `history-resume`：手动恢复会话。用户从历史列表选择会话时进入，以所选会话 ID 加载历史。

模式本身是客户端运行时状态，不跨应用重启持久化。

## 状态转换

| 用户行为 | 原模式 | 新模式 | 结果 |
| --- | --- | --- | --- |
| 启动或重启应用 | 任意 | `home-fresh` | 生成新 ID，AI 面板为空 |
| 打开邮件详情 | 任意 | `email-trace` | 切换到该邮件的追溯会话 |
| 从一封邮件切换到另一封邮件 | `email-trace` | `email-trace` | 切换到新邮件的追溯会话 |
| 关闭邮件详情、返回首页 | `email-trace` | `home-fresh` | 生成新 ID，AI 面板为空 |
| 主动选择历史会话 | 任意 | `history-resume` | 恢复用户选中的会话 |
| 查看历史后打开邮件 | `history-resume` | `email-trace` | 邮件上下文接管右侧会话 |
| 点击“新建会话”或清空当前面板 | 任意 | `home-fresh` | 生成新 ID，AI 面板为空 |

## 客户端结构

UI Store 作为会话导航状态的唯一来源，保存当前模式及其会话 ID，并提供语义明确的转换操作：

- `startFreshHomeConversation()`
- `openEmailConversation(emailId)`
- `resumeConversation(conversationId)`

邮件选择和关闭动作触发对应转换。AgentPanel 只消费当前解析后的会话 ID，不再使用固定 `mailboxId` 作为首页回退值，也不自行推断会话模式。

邮件会话的服务端标识沿用现有邮件 ID 关联方式，历史列表继续使用服务端 conversation ID。首页新会话使用运行时生成的唯一 ID，在用户发送第一条消息后按现有流程持久化，因此之后仍可从历史列表主动恢复。

## 数据与异常处理

- 不清理或迁移现有 `agent_conversations` 数据。
- 应用启动时即使历史查询仍在缓存，新的首页会话 ID 也不会匹配旧数据，因此面板保持为空。
- 切换模式时终止当前流式响应，避免旧会话内容写入新会话。
- 会话切换后，输入草稿按新会话 ID 隔离；新首页会话不会显示上一会话草稿。
- 邮件详情加载失败不回退到旧首页会话，仍保持该邮件关联的会话标识并展示现有错误状态。

## 验收与测试

自动化测试至少覆盖：

1. 应用初始状态生成新的首页会话 ID，并且不等于固定 mailbox ID。
2. 模拟应用重新初始化后得到另一个首页会话 ID。
3. 选择邮件后切换到该邮件的追溯会话。
4. 清除邮件选择后生成全新的首页会话，且不恢复之前首页或邮件会话。
5. 主动选择历史会话后准确恢复指定 conversation ID。
6. 从历史会话打开邮件后切换到邮件追溯会话。
7. 会话转换会清空当前渲染消息并终止未完成的流。
