# WeMail 企业通讯录组织树与批量写信设计

## 背景

当前企业通讯录已经同步并保存部门的 `parentId`、`childCount` 和联系人快照，部门接口也支持按 `parentId` 查询直属子部门。然而通讯录页面只请求并展示根节点，把根节点渲染为普通按钮，没有提供展开组织层级的能力。联系人查询又只匹配当前部门的直属成员，因此点击 `OrgGroups` 等容器节点时会显示“没有找到匹配的同事”，用户无法继续进入下级部门。

Coremail Web 的组织通讯录采用可展开部门树和成员表格：用户沿组织层级进入具体部门，浏览姓名、邮箱、手机和职位，并可勾选多人后发起邮件。WeMail 本次补齐这一核心浏览和批量写信流程，同时继续使用现有本地同步快照，不重新设计 Coremail 登录与同步协议。

## 目标

- 将根部门按钮列表升级为可展开、可选中的完整组织树。
- 按需加载直属子部门，避免首次打开时加载并渲染全部组织节点。
- 在成员表格中展示姓名、邮箱、手机和职位。
- 支持联系人分页、全局搜索和部门过滤。
- 支持选择当前页联系人，并将选中联系人带入现有新建邮件窗口。
- 对空部门、同步失败、请求失败和无本地快照提供明确且可恢复的状态。
- 保持现有通讯录搜索、收件人校验和 Coremail 同步链路兼容。

## 非目标

- 不汇总上级部门全部后代成员；选择部门只展示直属成员。
- 不增加通讯录联系人或部门的创建、编辑、删除和权限管理。
- 不增加联系人导出、群组管理或通讯录管理员能力。
- 不修改 Coremail 登录、目录发现和联系人同步协议。
- 不支持跨页全选；表头复选框只作用于当前页。
- 不从通讯录页面直接发送邮件；用户仍需在现有写信窗口审阅并发送。

## 方案选择

采用“本地快照 + 懒加载组织树”的方案。

### 备选方案一：一次性加载完整组织树

前端可以一次请求全部部门并在内存中构造树，实现较直接。但企业目录节点较多时会增加首屏传输、状态构造和渲染成本，也不利于节点级错误恢复，因此不采用。

### 备选方案二：展开节点时实时请求 Coremail

该方案数据最及时，但每次展开都会依赖 Coremail 登录态和网络质量，页面响应不稳定，也浪费已经建立的 SQLite 快照与离线浏览能力，因此不采用。

### 选定方案：本地快照懒加载

首次只请求根部门。用户展开节点时，通过现有 `GET /api/directory/departments?parentId=...` 获取直属子部门，并使用查询缓存保存成功结果。选择节点后分页读取直属成员。该方案复用现有数据模型，首屏开销小，也能在 Coremail 暂时不可用时继续浏览上次同步的数据。

## 页面结构

通讯录工作区保持三段式结构：顶部工具栏、同步状态栏、下方树与表格。

### 顶部工具栏

- 保留“企业通讯录”标题、全局搜索框和刷新按钮。
- 搜索框支持姓名、邮箱、拼音、部门和职务。
- 搜索输入使用短延迟触发，避免每次按键立即请求。
- 刷新按钮启动现有后台同步，不阻塞当前页面浏览。

### 同步状态栏

- 同步运行中显示已处理部门数和联系人数量。
- 同步成功显示最近同步时间。
- 同步失败但存在快照时保留旧数据，并显示非阻塞警告和重试入口。
- 完全没有快照时显示初始化说明和刷新按钮。

### 左侧组织树

- “全部同事”作为固定顶层入口，用于浏览全通讯录联系人。
- 部门节点由独立的递归树组件渲染。
- 有子节点的部门显示展开箭头；点击箭头只展开或收起，点击部门名称选择部门。
- 首次展开时请求直属子部门并显示节点内加载状态；成功加载的子节点由查询缓存保留。
- 默认展开企业根节点，使用户能立即看到下一层组织。
- 当前选中部门使用与现有 WeMail 视觉语言一致的珊瑚色弱高亮。
- 长部门名称截断显示，悬浮时通过 `title` 或提示组件显示完整路径。
- 子节点请求失败时只在该节点下显示重试，不清除其他已加载节点。

### 右侧成员表格

- 表格列为复选框、姓名、邮箱地址、手机号码、职位。
- 表格上方显示当前部门名称、成员总数和分页控制。
- 每页显示 50 人，提供上一页、下一页和当前页码。
- 选择“全部同事”时展示全局联系人；选择部门时只展示该部门直属成员。
- 空的叶子部门显示“该部门暂无成员”。
- 没有直属成员但存在子部门时显示“该部门暂无直属成员，请展开下级部门”。
- 窄窗口优先保留姓名和邮箱列，手机和职位列按可用宽度隐藏。
- 联系人列表请求失败时在表格区域显示重试，并保留组织树和已成功加载的数据。

## 搜索与分页

联系人查询契约增加 `offset`，响应增加 `total`：

```ts
interface DirectoryContactSearchResult {
  contacts: DirectoryContactSummary[];
  total: number;
  remoteAvailable: boolean;
}
```

现有不传 `offset` 的调用默认从 0 开始，保持兼容。`limit` 继续受服务端上限保护。

无搜索词时，仓储分别对全通讯录或指定部门执行计数和分页查询。存在搜索词时，沿用当前本地 FTS 与短词 `LIKE` 查询，并使用相同部门过滤条件计算总数。通讯录页面的搜索是全局搜索：输入关键词时不携带当前部门过滤，但保留树的视觉选中状态；清空搜索后恢复原部门和原页码。

远端增量搜索仍服务于写信收件人自动补全。组织通讯录页面优先展示本地同步快照，避免分页总数与远端增量结果产生不可解释的变化。

切换部门、输入新的搜索词或完成通讯录刷新后回到第一页。上一页和下一页只改变 `offset`，不重新加载部门树。

## 联系人选择与批量写信

- 每行复选框切换单个联系人选择状态。
- 表头复选框选择或取消选择当前页全部联系人。
- 选择状态按联系人 ID 保存，并按邮箱进行最终去重。
- 切换部门、发起新搜索、清空搜索或刷新通讯录时清空选择，避免把旧上下文的联系人误带入邮件。
- 存在选择时，表格上方显示“已选择 N 人”“写邮件”和“清除”操作。
- 双击联系人行可以直接以该联系人为唯一收件人打开新邮件。
- 点击“写邮件”调用现有 `startCompose`，不新建独立写信页面。

`ComposeOptions` 增加可选的 `prefilledTo`：

```ts
interface ComposeOptions {
  mode: ComposeMode;
  originalEmail?: Email | null;
  draftEmail?: Email | null;
  prefilledBody?: string;
  prefilledTo?: string;
}
```

新建邮件且没有草稿或原始邮件时，`useComposeForm` 使用 `prefilledTo` 初始化收件人字段。通讯录将联系人序列化为 `姓名 <邮箱>`，用逗号连接，并复用现有 `DirectoryRecipientInput` 的解析、去重和校验行为。通讯录永远只打开草稿供用户确认，不自动发送。

## 状态与错误处理

- 部门子节点和成员列表使用独立查询状态，一个区域失败不影响另一区域。
- 查询缓存保留已成功加载的部门节点，展开和收起不会重复请求。
- 同步失败但已有快照时继续展示旧数据，并明确标记数据可能不是最新。
- 同步完成后使部门、成员、计数和状态查询失效并重新获取，但不影响已打开的写信窗口。
- 没有任何部门或联系人快照时显示初始化空状态，而不是普通“没有找到”。
- 搜索无结果与远端不可用使用不同提示，避免把服务异常解释成没有联系人。
- 分页后若当前页因数据刷新变为空，自动回退到最后一个有效页。

## 组件与职责

### `DirectoryRoute`

负责页面级状态：搜索词、选中部门、页码和已选联系人。它组合查询与子组件，不承载递归树渲染细节。

### `DirectoryTree`

负责根节点、“全部同事”和递归部门节点。节点按需查询子部门，并暴露 `selectedDepartmentId` 与 `onSelect`。

### `DirectoryContactTable`

负责成员表格、加载/空/错误状态、分页控件、行选择和双击写信。

### `DirectorySelectionToolbar`

负责展示选择数量、清除操作和批量写信入口。

### 服务端目录查询

`DirectoryService` 继续作为 API 与仓储之间的边界。`DirectoryRepository` 增加分页结果和计数查询，但不修改数据库表结构和同步写入逻辑。

## 测试与验收标准

### 服务端测试

- 根部门和指定父部门查询返回正确直属子节点。
- 无搜索词的全局联系人查询正确应用 `offset`、`limit` 和 `total`。
- 部门联系人查询只返回直属成员，并给出该部门总数。
- FTS 搜索和短词搜索都返回与分页结果一致的 `total`。
- 搜索与部门过滤组合保持现有服务调用兼容。
- 不传 `offset` 时行为与现有调用一致。

### 前端测试

- 首次渲染根节点，并在展开节点时只请求该节点的直属子部门。
- 重复展开已加载节点不会产生多余请求。
- 点击箭头不改变选中部门，点击名称会选择部门并读取成员。
- 空的容器部门显示引导用户展开下级部门的提示。
- 表格正确展示姓名、邮箱、手机和职位，并在窄宽度下保留核心列。
- 分页控制使用正确的 `offset`，切换部门和搜索时回到第一页。
- 表头复选框只选择当前页，单行复选框正确更新选择数量。
- 切换部门、开始新搜索和刷新通讯录时清空选择。
- 点击批量“写邮件”按邮箱去重并通过 `prefilledTo` 打开现有写信窗口。
- 双击联系人以单一收件人打开写信窗口。
- 同步失败、有旧快照、无快照、节点失败和列表失败显示对应恢复操作。

### 完成定义

- 相关目录仓储、服务端路由和渲染端测试通过。
- `npm run typecheck` 通过。
- 客户端生产构建通过。
- 桌面端人工验收可沿 `example.com` 组织树逐层展开到叶子部门，看到成员表格，勾选多人并打开已正确预填收件人的写信窗口。
- 当前工作区中与本任务无关的智能助手改动不被覆盖或纳入提交。
