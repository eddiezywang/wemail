# 邮件列表筛选作用域设计

## 目标

收件箱、所有邮件及其他邮件目录的筛选条件只作用于当前目录视图。切换目录时清除筛选条件；进入“所有邮件”时默认展示完整列表，只有在该视图重新选择筛选条件后才进行筛选。

## 根因

筛选状态保存在全局 `useUIStore` 中，`MessageListView` 又会对任何传入查询结果统一执行本地筛选。因此，在收件箱设置的筛选会继续作用于“所有邮件”的查询结果，即使虚拟目录查询本身没有携带这些参数。

## 方案

为筛选状态增加当前视图作用域。作用域使用当前路由路径标识：

- 作用域匹配当前路径时，读取并应用已有筛选。
- 作用域不匹配时，当前视图读取默认筛选，并清除旧作用域。
- 筛选弹窗、红点、路由查询参数和 `MessageListView` 使用同一份当前作用域筛选。
- 目录路径不变时，切换分类或搜索参数不改变筛选；切换目录路径时清除筛选。

## 数据流

```text
当前 pathname
  -> 当前邮件筛选作用域 hook
  -> 当前作用域筛选 / 默认筛选
  -> 邮件路由查询参数
  -> MessageListView 本地筛选
```

这样收件箱筛选不会影响所有邮件；用户在所有邮件视图重新选择筛选后，筛选会以所有邮件为作用域生效。

## 测试与验收

- 收件箱设置任一筛选后，切换到所有邮件，所有邮件列表仍显示未筛选数据。
- 进入所有邮件后重新设置筛选，列表才按新筛选条件过滤。
- 切换目录后筛选状态被清除，筛选按钮红点消失。
- 保持现有收件箱筛选查询参数行为不变。
