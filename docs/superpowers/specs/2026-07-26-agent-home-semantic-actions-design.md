# Agent 首页语义行动设计

## 背景

当前 Agent 首页展示的三条建议：

- 打开摘要中心，处理待摘要邮件
- 总结最近 24 小时的邮件
- 查看未完成的邮件待办

由账户摘要状态触发，并以固定组合返回。第一项是页面导航，后两项只是固定自然语言提示。它们不是从邮件内容中发现的行动，却以与上下文行动相同的样式展示，造成“AI 已从邮件中提炼行动”的错误预期。

本设计替代
`2026-07-23-agent-home-contextual-suggestions-design.md`
中以下约定：

- “当天邮件”候选范围；
- 当天没有候选时退回通用账户级建议；
- 每条首页建议必须绑定一个固定邮件 ID 列表；
- 点击建议时只以关联邮件 ID 作为执行范围。

会话生命周期、轻量提示词外观、两阶段生成、缓存和交互后冻结等未被本设计明确修改的部分继续有效。

## 核心概念

首页展示的是“语义行动”，不是产品功能入口，也不等同于单封邮件待办。

语义行动是由邮件信号推导出的可执行目标。它可以作用于：

- 一封邮件；
- 多封已知邮件；
- 执行时根据查询条件动态命中的邮件集合。

系统必须区分两个互不替代的范围。

### 发现范围

发现范围决定系统根据哪些邮件判断“现在值得建议什么”。

- 优先使用最近 24 小时内、收件箱中的未读邮件。
- 若不足以形成三条可靠建议，扩展到最近 7 天内、收件箱中的未读邮件。
- 第 2 至第 7 天的数据只用于补足，不得挤掉最近 24 小时内同等质量的建议。
- 已读邮件不能用于提取新的明确待办。
- 发件箱、营销邮件、普通无行动通知和没有有效智能结果的邮件不能用于凑数。

### 执行范围

执行范围决定用户点击后 Agent 可以读取和处理哪些邮件。

- 执行范围由每条语义行动单独声明。
- 可以限定为未读邮件，也可以包含已读和未读邮件。
- 可以按时间、邮箱文件夹、类别、发件人、主题、线程或其他受支持的搜索条件限定。
- 可以使用发现阶段的固定邮件 ID，也可以在执行时重新运行动态查询。
- 发现行动的未读邮件只是证据，不自动限制执行范围。

例如，一封新的未读告警可以触发“汇总过去 24 小时全部告警”。该行动执行时可以查询过去 24 小时内所有已读和未读告警，而不是只分析触发它的未读邮件。

## 行动类型

### 提取型行动

提取型行动来自未读邮件中明确要求收件人完成的事项，例如回复、确认、提交材料或处理截止任务。

约束：

- 必须有未读来源邮件。
- 必须来自已有摘要行动项、待办提取、回复判断或其他可验证的智能结果。
- 不得根据已读邮件重新制造待办。
- 允许一条行动聚合多封未读邮件中的同类待办。

### 分析型行动

分析型行动来自多封邮件之间有意义的模式，例如：

- 汇总过去 24 小时的系统告警；
- 按系统和严重程度统计告警；
- 归并重复问题并列出共同原因；
- 汇总项目进度、风险和阻塞项；
- 对某类客户邮件生成回复策略。

约束：

- 必须能说明由哪些未读信号触发。
- 执行范围可以查询已读和未读邮件。
- 不能只因为存在邮件或摘要任务就生成泛化建议。
- 建议应描述用户目标，而不是产品页面或内部任务。

## 数据契约

扩展 `AgentSuggestion`，使发现证据与执行范围成为不同字段：

```ts
type AgentSemanticActionKind = "extracted" | "aggregate";

interface AgentActionDiscovery {
  emailIds: string[];
  primaryWindow: "24h" | "7d";
  mailState: "unread";
}

interface AgentActionScope {
  mode: "fixed" | "query";
  emailIds?: string[];
  query?: {
    receivedWithin?: "24h" | "7d";
    mailState?: "unread" | "all";
    folder?: "inbox";
    category?: string;
    sender?: string;
    subject?: string;
    threadIds?: string[];
  };
}

interface AgentSuggestion {
  id: string;
  label: string;
  prompt: string;
  kind: AgentSemanticActionKind;
  discovery: AgentActionDiscovery;
  executionScope: AgentActionScope;
}
```

所有服务端返回的邮件 ID 和查询条件必须限制在当前账户。服务端负责校验模型结果，客户端不能自行扩大范围。

`open_digest_center`、`open_settings` 等产品导航动作不再作为首页语义行动返回。它们可以存在于独立的功能入口，但不与语义行动混排。

## 生成流程

### 1. 候选查询

服务端查询最近 7 天收件箱未读邮件及以下结构化信息：

- 邮件 ID、接收时间、主题、发件人和线程 ID；
- 摘要的意图、注意类型、行动项和紧急程度；
- 待办提取结果及完成状态；
- 回复判断与是否已回复；
- 分类结果；
- 已有处理状态。

查询结果分为最近 24 小时和第 2 至第 7 天两组。完整正文不进入首页行动生成输入。

### 2. 确定性信号与规则结果

规则阶段立即构建可用行动：

- 从有效智能结果中提取明确待办；
- 按主题、分类、线程和意图识别可以聚合的邮件组；
- 最近 24 小时优先；
- 只有不足三条时才使用第 2 至第 7 天候选；
- 去除重复、已完成、已回复和低价值通知；
- 没有可靠行动时返回空数组，不使用固定建议补位。

规则行动必须同时给出发现证据和执行范围。

### 3. AI 聚合增强

模型接收评分最高的有限候选及其结构化智能结果，用于：

- 合并同类待办；
- 发现跨邮件统计、归纳和比较目标；
- 为行动生成简短、明确的用户可见标签；
- 为 Agent 生成完整执行指令；
- 选择固定范围或受约束的动态查询范围。

模型不能：

- 引用候选集合外的发现证据；
- 生成不受数据支持的待办；
- 生成产品导航入口；
- 输出当前账户之外的邮件 ID；
- 输出契约不支持的任意查询表达式。

模型结果验证失败时继续使用规则结果。

### 4. 排序与补足

最多展示三条，按以下顺序排序：

1. 最近 24 小时内有明确截止时间或高紧急度的提取型行动；
2. 最近 24 小时内证据充分的分析型行动；
3. 最近 24 小时内其他明确提取型行动；
4. 第 2 至第 7 天的对应行动。

“补足”只表示扩大候选时间窗，不表示必须凑满三条。

## 点击与执行

点击首页语义行动后：

1. 保持在当前首页 Agent 会话，不自动打开单封邮件。
2. 将行动目标、发现证据和执行范围一起提交给 Agent。
3. 服务端重新验证账户和范围。
4. 固定范围直接加载指定邮件；动态范围通过邮件搜索能力在执行时查询。
5. Agent 在读取匹配邮件后完成汇总、统计、起草或其他目标。
6. 结果提供可追溯的来源邮件；用户需要时再打开详情。

单封邮件只是固定范围恰好只有一个邮件 ID 的特例，不采用独立执行模型。

外部发送、删除、上传或其他高风险操作继续遵循现有确认机制。点击语义行动本身不代表用户批准这些外部操作。

## 首页展示

- 保留最多三条轻量按钮。
- 标签描述目标，例如“汇总过去 24 小时的系统告警”。
- 不显示“摘要中心”“设置”等内部页面名称。
- 可以在标签或辅助文本中展示聚合规模，例如“涉及 12 封邮件”，但不能用待摘要数量冒充行动数量。
- 无可靠行动时不展示按钮，也不使用固定问题替代。
- 用户开始输入、点击建议、切换邮件或恢复历史会话后，本轮建议冻结。

## 缓存与失效

候选指纹至少包含：

- 账户 ID；
- 用户时区下的 24 小时和 7 天边界；
- 两个时间窗内的未读候选邮件 ID；
- 摘要、待办、回复判断、分类和完成状态版本；
- 语义行动生成版本。

新邮件、已读状态、待办完成状态或相关智能结果变化时使缓存失效。相同指纹复用缓存，同一指纹只允许一个 AI 聚合任务。

动态执行范围不固化为候选指纹的一部分；点击后必须重新查询，保证结果反映执行时状态。

## 失败处理

- 候选查询失败：返回空建议并记录不含正文的错误。
- AI 未配置、超时或输出非法：使用规则结果。
- 动态查询无匹配结果：Agent 明确说明当前没有匹配邮件，不扩大查询范围。
- 部分来源邮件在点击前被删除或移出账户：忽略不可用来源，并在没有剩余数据时停止执行。
- 不得回退到旧的固定三项建议。

## 测试策略

### 候选与规则测试

- 最近 24 小时收件箱未读邮件优先于第 2 至第 7 天邮件。
- 只有不足三条可靠行动时才使用第 2 至第 7 天候选。
- 已读邮件不能产生提取型行动。
- 发件箱、营销邮件、已完成待办和已回复事项被排除。
- 同类邮件可以形成多邮件分析型行动。
- 没有可靠行动时返回空数组。

### 聚合与契约测试

- 提取型行动的发现来源全部为未读邮件。
- 分析型行动允许声明 `mailState: "all"` 的动态执行范围。
- 模型不能引用候选外发现证据。
- 非法邮件 ID、跨账户范围和不支持的查询条件被拒绝。
- 输出最多三条且不通过固定建议补足。

### API 与客户端测试

- 首页响应包含 `kind`、`discovery` 和 `executionScope`。
- 首页不返回摘要中心、设置或固定“查看待办”入口。
- 点击建议不打开邮件详情。
- 点击建议向 Agent 发送目标和经过验证的执行范围。
- 动态范围在点击时重新查询。
- 空建议状态不显示固定替代按钮。
- 选中邮件后的邮件级建议行为保持兼容。

### 端到端场景

1. 最近 24 小时存在多封告警，其中部分已读、部分未读。
2. 未读告警触发“汇总过去 24 小时全部告警”。
3. 点击后首页会话查询并读取全部匹配告警。
4. 输出按系统和严重程度统计，并能追溯到来源邮件。
5. 应用不打开任一单封邮件详情。

## 发布与兼容

- 服务端先扩展契约，客户端兼容缺失新字段的邮件级旧建议。
- 首页只接受完整的语义行动契约；旧账户级固定建议不再渲染。
- 选中邮件后的现有上下文建议不在本次范围内，但后续可以迁移到同一契约。
- 发布期间若新首页服务不可用，显示空建议状态，不恢复固定入口。

## 已确认决策

- 采用规则评分加 AI 聚合，而不是纯规则或全量原文直读。
- 发现范围只使用收件箱未读邮件。
- 最近 24 小时优先，不足时扩展到最近 7 天。
- 提取待办只能来自未读邮件。
- 执行范围由行动单独定义，可以读取已读和未读邮件。
- 首页行动可以针对一封、多封或动态查询得到的邮件集合。
- 点击后留在首页会话执行，不强制打开邮件详情。
- 没有可靠行动时不凑满三条。
- 固定摘要入口和固定提示词不再作为首页行动展示。
