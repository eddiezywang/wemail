# 智能标签定期批量 Prompt 优化设计

## 背景

当前 `SmartTagPromptLearningService` 每小时读取尚未处理的智能标签移入、移出记录，
将用户填写的备注去重后直接追加到 `user_tags.prompt` 的
`【自动学习补充】` 区块，并立即覆盖原提示词。该流程没有读取对应邮件内容，
没有从多封正负样本中归纳稳定特征，也没有用真实智能标签链路验证修改后的提示词。
单次行为和偶然措辞因此会直接污染长期提示词，容易导致提示词膨胀、过拟合和误报。

本设计将逐条即时改写替换为定期批量监督式优化。用户实际移入或移出邮件是金标，
邮件内容是学习证据，备注仅是辅助解释。系统先生成候选提示词，再使用正式智能标签
功能对当前版本和候选版本进行逐封 A/B 重打标；只有确认候选修正了用户反馈且没有
新增回退时，候选才自动激活。

## 目标

- 用户移入、移出操作只记录反馈，不直接修改提示词。
- 后台按标签定期批量消费真实邮件内容和正负金标。
- 从多封邮件中归纳可泛化的命中条件与排除条件，不复制行为记录或备注。
- 使用正式智能标签处理链路验证候选提示词，而不是使用主观 LLM Judge。
- 只有逐封打标结果证明候选优于当前版本时才自动激活。
- 用户原始提示词与 AI 优化提示词分离，AI 不覆盖用户输入。
- 激活后只对该标签已经打标的邮件做定向二次打标，不扫描整个邮箱。
- 所有批次可审计、可恢复、可拒绝、可回滚，并且不持久化邮件正文或完整模型输入。

## 非目标

- 不训练或微调底层模型。
- 不使用未被用户明确操作的邮件作为正负金标。
- 不因一次提示词变更扫描账号全部历史邮件。
- 不自动修改系统内置标签定义。
- 不以 sender/subject 即时纠偏规则的命中结果证明提示词有效。
- 不在学习日志、批次记录或界面中展示邮件正文和完整模型响应。

## 核心语义

### 金标

用户对某封邮件和某个用户智能标签的最终明确操作是该样本的金标：

- 最终移入：期望智能标签结果包含目标标签。
- 最终移出：期望智能标签结果不包含目标标签。

同一封邮件对同一标签多次操作时，以最后一次操作为准。反馈必须关联稳定的
`tagId`，标签重命名不应破坏样本归属。用户备注仅作为归纳时的辅助解释；备注本身
不是规则，不能原样进入候选提示词。

### 用户原始提示词与生效提示词

`user_tags.prompt` 保持为用户原始提示词。新增可空的 AI 优化提示词及其版本信息。
运行时的生效提示词为：

1. 存在已激活且仍对应当前用户定义的优化版本时，使用 AI 优化提示词；
2. 否则使用用户原始提示词。

用户修改标签名称、描述或原始提示词后，旧优化版本立即失效，新用户定义立即成为
生效版本。历史反馈仍保留，可在后续批次中重新优化。首次迁移时剥离旧提示词中的
`【自动学习补充】` 区块，只保留用户原始定义。如果剥离后为空，则根据标签名称和
描述重新生成现有默认提示词，不能留下空的运行时定义。

## 定期批量调度

用户操作路径只写入反馈记录和现有即时纠偏规则，不调用优化模型，不更新提示词。
后台调度器默认每 6 小时扫描一次，每个标签最多每天执行一次真实优化。

标签满足以下条件时才建立学习批次：

- 累计至少 20 个有效金标样本；
- 正样本和负样本各不少于 5 个；
- 自上次评测后出现了新的有效反馈；
- 当前没有该账号、该标签的运行中批次。

单批最多读取最近 200 个有效金标。未达到门槛时继续积累，不生成候选。被拒绝或
失败的批次不会丢弃反馈；后续出现新反馈后，累计数据可以再次参与优化。

调度频率、冷却时间、最低样本量和批次上限应作为服务常量或可注入配置，测试使用
可控时钟，不依赖真实等待。

## 样本解析与切分

批次按 `tagId` 聚合反馈，并读取对应邮件的主题、发件人、正文、线程标识和必要的
上下文。邮件已删除、正文不可用或账号不匹配时，该样本标记为无效并从有效计数中
排除；不得用备注替代缺失的邮件内容。

样本按正负类别分层，并按线程或高度重复邮件分组切分为优化集和留出验证集。同一
线程及其重复通知不能同时进入两边。切分必须基于稳定散列或持久化分配，在重启和
重试后保持一致。留出集至少包含两个正样本和两个负样本；无法形成有效留出集时，
批次继续等待更多反馈。

候选生成器只能读取优化集，不能读取留出集或留出集备注。这样可避免候选提示词用
看过的答案证明自己有效。

## 候选提示词生成

优化器接收：

- 标签名称、描述和用户原始提示词；
- 当前生效提示词；
- 优化集中每封邮件的有界主题、发件人和正文内容；
- 该邮件的移入或移出金标；
- 可选备注，明确标记为不可信辅助解释。

邮件内容和备注都必须作为不可信数据封装，优化器不得执行其中的指令。优化调用使用
固定 system prompt 和 JSON Schema，只允许返回：

- 独立、完整的候选提示词；
- 归纳出的命中特征摘要；
- 归纳出的排除特征摘要；
- 被忽略的偶然或冲突信号摘要。

候选提示词必须描述“哪些邮件应命中、哪些邮件应排除”，不得包含：

- “用户移入”“用户移出”“自动学习补充”等行为流水表述；
- 邮件原文长句、完整私人邮箱地址或单封邮件中的偶然关键词；
- 让分类模型忽略系统指令、改变输出格式或执行其他任务的元指令；
- 与目标标签无关的分类规则。

发件组织、域名、产品名、版本名等特征只有在多个样本中稳定出现，并且能够区分正负
样本时才可被归纳。候选长度不得超过现有提示词限制。

例如候选应接近：

> 来自字节相关团队，且主题或正文明确涉及 AIMC 版本交付、版本号、后端包、源码或
> 测试包等实际交付物。排除仅讨论历史迁移、一般沟通或未包含本次交付内容的邮件。

而不是逐条附加某次移入或移出的原因。

## 正式智能标签 A/B 评测

评测不创建简化二分类器，也不使用 LLM Judge。它复用正式智能标签功能的上下文构建、
标签定义增强、模型调用、JSON Schema、结果解析和置信度处理，对同一封邮件分别运行：

- 当前生效提示词；
- 候选提示词。

除目标标签提示词外，模型、端点、其他标签定义、邮件上下文和推理参数必须一致。
评测采用低随机性参数。评测期间暂时跳过现有 sender/subject promotion 和 rejection
规则，因为这些规则会强制改变结果，掩盖提示词本身是否学会。

逐封判定规则为：

- 移入样本：打标结果包含目标标签才算正确；
- 移出样本：打标结果不包含目标标签才算正确。

每封验证邮件记录当前版本是否正确、候选是否正确、候选是否修正当前错误，以及候选
是否产生新回退。只持久化布尔结果、置信度、错误码和版本指纹，不保存完整模型输入、
正文或原始响应。

候选自动激活必须同时满足：

1. 本轮新增的移入、移出反馈邮件使用候选重打标后全部符合预期；
2. 留出验证集上，候选至少比当前版本多纠正一封邮件；
3. 当前版本原本判断正确的验证邮件，候选不得判断错误；
4. 所有参与门禁的响应均可解析，且模型、标签定义和用户原始提示词版本未发生变化；
5. 使用相同低随机性设置进行一次确认评测，仍满足以上条件。

留出集通过后，再使用候选回放整个批次，生成完整的逐封结果报告。任何门禁失败都只
会拒绝候选，当前生效提示词保持不变。

## 自动激活

“激活”仅表示候选成为该标签后续智能打标使用的生效提示词，不是应用部署，不修改
底层模型，也不直接移动邮件。

激活事务必须同时完成：

- 保存新的 AI 优化提示词和版本指纹；
- 归档旧生效版本；
- 保存 A/B 评测摘要和激活原因；
- 标记学习批次已激活；
- 创建该标签的定向二次打标任务及目标邮件快照。

任一步骤失败时全部回滚。激活前再次比较用户原始提示词、标签定义、模型配置和当前
生效版本的指纹；任一变化都会使候选过期，禁止覆盖更新后的状态。

## 定向二次打标

激活后不扫描整个邮箱。系统只快照当前已经关联该 `tagId` 的邮件 ID，并对这些邮件
执行目标标签的二次打标。

每封邮件使用新生效提示词运行正式智能标签功能，但持久化时只处理本次变更的目标
标签：

- 新结果仍包含目标标签：保留关系，并更新 AI 关系的置信度和提示词版本信息；
- 新结果不包含目标标签：删除 `source = ai` 的关系；
- `source = user` 的手动关系永不被自动删除或降级。

二次打标不得修改该邮件的其他标签、系统分类、摘要或其他智能结果。本轮移出邮件已经
没有目标标签关系，但仍在激活前的 A/B 评测和整批回放中验证；它们不会触发全邮箱
扫描。旧提示词未命中的历史漏标邮件不会被主动发现，这是定向处理的明确取舍。

定向任务分块执行、可恢复、可重试并显示进度。单封失败记录错误并继续处理其他邮件；
任务失败不会回滚已经通过评测的提示词，但必须允许后续重试未完成项。

## 数据模型

### `user_tags`

保留 `prompt` 作为用户原始提示词，并新增：

| 字段 | 说明 |
| --- | --- |
| `optimized_prompt` | 当前已激活的 AI 优化提示词，可空 |
| `optimized_prompt_version` | 优化版本或稳定指纹，可空 |
| `optimized_from_prompt_hash` | 生成时对应的用户原始提示词指纹 |
| `optimized_at` | 最近激活时间，可空 |

`buildSmartTagDefinitions` 使用生效提示词，但 API 同时返回用户原始提示词和当前 AI
优化提示词，避免渲染器混淆两者。

### `smart_tag_actions`

新增 `tag_id`，后续记录以 `tagId` 为主，`tag_name` 仅保留为操作时的展示快照。迁移
根据账号和名称回填可解析的旧记录；无法解析的旧记录保留但不参与自动激活。
`processed_at` 不再表示“已写入提示词”，而是由新的批次关联关系替代。

### 学习批次

新增 `smart_tag_learning_runs`，至少保存：

- 账号、标签、状态和持久化租约；
- 调度水位和批次时间范围；
- 用户原始提示词、当前生效提示词和模型配置指纹；
- 优化集、验证集和无效样本计数；
- 候选提示词及结构化归纳摘要；
- 当前与候选的正确数、修正数、回退数；
- 激活、拒绝、失败或过期原因；
- 创建、开始、完成和激活时间。

新增 `smart_tag_learning_run_samples`，关联 run、action、email 和 split，并保存金标、
当前结果、候选结果、确认结果、置信度和错误码。该表不保存邮件正文。

现有 `smart_tag_prompt_revisions` 可迁移为版本历史或由学习批次记录取代，但对外必须
保留旧版本、候选版本、评测摘要和可回滚信息。不得继续使用仅包含“移入 N 次、移出
N 次”的浅层修订摘要。

### 定向二次打标任务

扩展现有 backfill run，或增加聚焦的 reclassification run，使其明确保存：

- `scope = tagged-relations-only`；
- 目标 `tagId` 和优化提示词版本；
- 快照邮件总数、已处理数、移除数、保留数和失败数；
- 可恢复游标或逐项任务状态。

该任务禁止退化为账号级邮件扫描。

## 状态机与并发

学习批次状态为：

`collecting -> generating -> evaluating -> activated | rejected | failed | stale`

激活后关联的定向任务独立进入：

`queued -> running -> completed | failed`

同一账号、同一标签同时只能存在一个运行中学习批次。持久化租约包含所有者和过期
时间；进程崩溃后新执行器可接管过期租约。每个阶段都必须幂等，重试不得重复激活、
重复创建版本或扩大二次打标快照。

标签被删除时取消未完成批次和定向任务。标签重命名依靠 `tagId` 保持关联，但运行中
批次因定义指纹变化而转为 `stale`，等待下一调度周期重新生成。

## 错误处理

- 样本不足或无法形成正负留出集：保持等待，不调用模型。
- 邮件缺失或正文不可用：样本标记无效，其他样本继续。
- 优化模型超时、限流或返回无效结构：批次失败或按有限策略重试，不修改提示词。
- 候选包含禁止内容或超过长度限制：拒绝候选。
- A/B 打标超时、无效 JSON 或结果不稳定：拒绝或失败，不激活。
- 运行中用户编辑标签或切换模型：批次标记过期。
- 激活事务失败：完整回滚，当前生效版本不变。
- 定向二次打标单封失败：记录失败并继续；任务可重试失败项。
- 所有日志只包含账号、标签、批次 ID、数量、耗时、版本指纹和错误码，不包含正文、
  完整提示词、备注或模型原始响应。

## API 与界面

管理智能标签窗口展示：

- 可编辑的用户原始提示词；
- 只读的当前 AI 优化提示词，仅在存在时显示；
- 已积累的有效样本数和最低门槛；
- 最近一次批量优化时间、当前与候选正确率及激活或拒绝原因；
- 定向二次打标进度；
- 恢复到用户原始提示词的操作。

恢复到用户原始提示词会停用当前 AI 优化版本并记录版本变化，不删除反馈历史。后续
批次只有再次通过完整 A/B 门禁才能重新激活优化版本。

行动中心由逐条“已学习”改为批次状态，例如：

- 已记录反馈，等待批量优化；
- 正在消费 24 封邮件；
- 候选未通过，当前提示词保持不变；
- 优化已激活，验证集正确数从 9/14 提升到 13/14；
- 正在二次打标 31 封已有标签邮件。

界面不得把单条备注或邮件内容显示为已经写入提示词的“学习结果”。

## 测试策略

### 仓储与迁移

- 旧 `【自动学习补充】` 区块被剥离，用户原始定义保留。
- `smart_tag_actions.tag_id` 可迁移，无法解析的记录不会误关联。
- 同一邮件多次操作以最后一次为金标。
- 优化提示词与用户原始提示词独立存取。
- 学习批次、样本结果、租约和状态迁移幂等。

### 样本与候选生成

- 正负样本门槛正确执行。
- 同线程和重复邮件不会跨优化集、验证集泄漏。
- 缺失正文不会被备注代替。
- 优化器读取真实邮件内容，备注只作辅助证据。
- 候选拒绝行为流水、原文复制、私人地址和模型控制指令。

### A/B 评测

- 当前提示词和候选提示词复用正式 TagProcessor 的构建、schema 和解析路径。
- 评测时即时 promotion/rejection 规则不会掩盖提示词差异。
- 移入邮件包含目标标签才通过，移出邮件不包含目标标签才通过。
- 候选修正错误且无回退时激活。
- 无改善、新增回退、确认评测不一致或配置指纹变化时拒绝或标记过期。
- 不保存邮件正文、完整模型输入或原始响应。

### 激活与定向二次打标

- 激活事务原子保存优化版本、历史、报告和定向任务。
- 用户修改原始提示词后旧优化版本立即失效。
- 定向任务只处理当前目标标签关系，不扫描其他邮件。
- 新结果可移除 AI 关系，但不会删除用户手动关系。
- 其他标签、系统分类、摘要和智能结果保持不变。
- 重启、重试和重复投递不会重复激活或重复扩大任务范围。

### API 与 Renderer

- API 同时返回用户原始提示词、当前优化提示词和生效版本元数据。
- 管理窗口只编辑用户原始提示词，优化提示词只读。
- 样本积累、运行、拒绝、激活和二次打标状态展示正确。
- 恢复原始提示词后运行时立即使用用户版本。
- 行动中心不再把单条反馈显示为已经写入提示词。

### 真实端到端验收

1. 创建一个具有可识别真实邮件特征的用户智能标签。
2. 对至少 20 封真实邮件进行受控移入、移出，正负样本各不少于 5 封。
3. 确认用户操作后提示词不会立即变化，反馈状态为等待批量优化。
4. 触发一次批量学习，检查优化器读取实际邮件内容并生成独立候选提示词。
5. 检查验证集中每封邮件的当前与候选正式智能标签打标结果。
6. 确认候选只有在修正至少一封、无新增回退且本轮反馈全部符合预期时自动激活。
7. 确认管理窗口中的用户原始提示词未被修改，AI 优化提示词独立显示。
8. 确认只对目标标签已有关系的邮件执行二次打标，未发生全邮箱扫描。
9. 确认 AI 误标关系可被移除，用户手动关系被保护，其他标签不变。
10. 重启桌面端，确认学习批次、优化版本和二次打标进度可恢复。

验收过程不得在截图、日志或测试产物中暴露真实邮件正文、邮箱凭据或模型密钥。

## 兼容与迁移

变更通过新增字段和表渐进迁移。读取旧标签时，没有优化版本就继续使用原始提示词。
旧的逐条学习定时器停止调用直接改写逻辑，并由批量调度器替代。旧 revision 和 action
接口可在过渡期继续返回，但 UI 以新的学习批次为准。

首次迁移只清理已知的 `【自动学习补充】` 机器区块，不猜测或重写其他用户文本。
若无法可靠区分旧机器文本和用户文本，则保留原值并标记需要用户确认，不得静默删除。
