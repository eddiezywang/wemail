# WeMail 同步恢复与诊断日志优化设计

日期：2026-07-28

## 目标

本次改动解决两个已经确认的线上问题：

1. 历史邮件分页同步期间 IMAP 连接中断后，启动同步直接进入 `recoverable-failure`，没有利用已保存的 checkpoint 自动续跑；后续实时同步即使成功，顶部失败提示仍不会消失。
2. 应用把高频智能任务、队列重试和性能状态变化全部持久化为本地日志，缺少大小轮转、总容量限制和临时调试模式，导致单日日志达到数十至上百 MB。

同时在“高级设置 → 诊断”中增加调试模式开关。调试模式开启后持续 30 分钟，可手动提前关闭，到期自动恢复普通日志策略。

## 非目标

- 不改变 WeCLI 审计、自动化执行记录和业务数据库的保留语义。
- 不记录邮件正文、HTML、附件内容、密码、令牌或 API Key。
- 不为普通日志增加远程上传能力。
- 不清理邮件缓存、专项同步错误记录或数据库业务数据。

## 方案选择

采用动态日志控制方案：日志策略由 control-plane 中的 `AppLogger` 管理，并通过本地控制面 API 暴露状态查询和模式切换。设置页直接调用该 API，无需重启 Electron 或后台服务。

没有采用环境变量方案，因为它要求重启服务；也没有采用仅 Electron 主进程过滤的方案，因为主要日志由 control-plane 产生，无法完整控制。

## 同步断线恢复

### 分页同步续跑

`Mail Core sync worker.runPagedWindow` 把一次分页扫描视为可恢复运行：

1. 首次连接并读取数据库中已有的 metadata checkpoints。
2. 创建 provider 分页迭代器，逐页提交邮件、游标和 checkpoint。
3. 当迭代器抛出 `NoConnection` 时，安全关闭旧连接并重新连接。
4. 重新从数据库读取 checkpoints，并创建新的分页迭代器。已提交页面不会重复产生首次发现事件，未完成文件夹从 checkpoint 继续。
5. 单次窗口运行最多自动重连一次。第二次连接失败向上抛出，由启动协调器记录可恢复失败，避免无限重试。

鉴权错误不进入自动重连分支，继续触发现有凭据恢复流程。非连接类 provider 错误保持现有错误语义。

只有所有分页迭代器正常完成后，才调用 `markMetadataSyncSucceeded` 并发布 `metadata-synced`。

### 启动状态恢复

`StartupSyncCoordinator` 在进入 `recoverable-failure` 后继续观察账户级同步成功信号。后续 `live-poll`、`live-idle` 或手动同步证明连接已经恢复时，协调器启动一次去重的恢复运行：

- 已有恢复运行时直接复用，不并发启动第二次。
- 重新执行近期元数据校验。
- 历史阶段利用 checkpoint 续跑。
- 继续正文 worker 和 intelligence ready 阶段。
- 全链路完成后发布 `settled`，清除 `errorCode`，更新 `settledAt`。

UI 仍只根据启动状态展示提示；由于状态能够回到 `settled`，无需在组件内增加基于时间或本地猜测的隐藏逻辑。

为避免协调器把自己运行中的 `metadata-synced` 当作外部恢复信号，恢复触发器只在当前状态为 `failed` 且没有 active run 时接受同步成功事件，并通过微任务或下一事件循环启动。

## 日志策略

### 普通模式

普通模式保留对故障定位和审计真正有价值的记录：

- 应用启动、退出、版本和迁移结果。
- 同步运行最终汇总。
- 重连发生、重试耗尽、鉴权失败和最终同步失败。
- 队列任务最终失败。
- 自动化及外部变更继续进入既有审计存储。
- 安全、授权和数据保留任务失败。

以下高频事件降为 `debug`，普通模式不持久化：

- 每封邮件的 `*-context-built` 与 `*-ok`。
- intelligence orchestrator 的逐任务入队信息。
- queue runner 的正常派发及中间重试过程。
- watcher 每分钟轮询触发。
- 历史同步逐页提交信息。

性能 governor 的暂停和恢复事件保留为普通日志，但按事件类型及原因执行一分钟限频。限频窗口结束后的下一条记录包含 `suppressedCount`。

重复错误采用有界抑制：同一事件和稳定错误签名只记录首次，随后在一分钟窗口内计数；窗口后的下一条或最终失败记录被抑制数量。错误签名不得包含邮件主题、正文、联系人或其他内容字段。

### 调试模式

调试模式属于本机运行状态：

- 开启时立即生效，不重启服务。
- 固定 30 分钟后自动关闭。
- 用户可以提前关闭。
- control-plane 返回 `enabled`、`expiresAt` 和剩余秒数。
- 服务重启后默认关闭，不跨重启延续，避免用户遗忘。
- 调试模式只放开已有的安全结构化 debug 事件，仍执行深度脱敏。

设置页每隔合理时间刷新剩余时间，在到期时自动更新开关和文案。

### 文件轮转与保留

日志文件采用日期和大小双重轮转：

- 主文件仍为 `app-YYYY-MM-DD.log`。
- 文件达到 20 MB 后使用同日序号文件，例如 `app-YYYY-MM-DD.1.log`。
- 写入前判断预计大小，避免新记录明显突破阈值。
- 普通应用日志保留 14 天。
- 日志目录总容量上限为 200 MB；超过上限时按修改时间从旧到新删除应用日志，保留当前正在写入的文件。
- 保留任务识别主文件和带序号的轮转文件。

本次迁移只删除用户数据目录 `logs` 下匹配 `app-YYYY-MM-DD.log` 和 `app-YYYY-MM-DD.N.log` 的历史应用日志。不会删除其他文件。删除属于不可恢复操作，执行结果在交付说明中明确列出。

## 控制面接口

增加本地诊断设置接口，沿用现有本地 API 的鉴权和错误处理：

- `GET /api/diagnostics/logging`：返回当前模式、到期时间、保留天数、单文件上限和总容量上限。
- `PUT /api/diagnostics/logging`：请求体 `{ "debugEnabled": boolean }`。开启时服务计算 30 分钟后的 `expiresAt`；关闭时立即清除。

日志器提供运行时控制对象，而不是重新创建 logger，确保已经注入各服务的 logger 引用即时读取最新模式。

## 设置页交互

入口位于“高级设置 → 诊断”，沿用当前设置页的克制、工具型视觉语言：

- 标题为“调试日志”。
- 使用现有 `Switch`，避免增加新的导航层级。
- 关闭时说明普通模式只保留关键运行与错误信息。
- 开启时显示“将在 XX:XX 自动关闭”及剩余时间。
- 明确提示不会记录邮件正文、密码或令牌。
- API 调用期间禁用开关；失败时恢复服务端状态并显示 toast。
- Web 非桌面运行环境仍可调用本地 control-plane API；若接口不可用则禁用开关并显示不可用状态。

## 错误处理

- 日志写入失败永远不能影响邮件和 UI 主流程。
- 轮转文件检查或清理失败采用 best effort，并以可用日志通道记录一次警告，禁止递归写日志。
- 调试模式接口只接受布尔值，非法请求返回 400。
- 自动到期由 logger 在读取模式和写日志时共同校验，不依赖仅存在于 UI 的定时器。
- 同步恢复第二次断线后保留 checkpoint，下一次恢复仍可继续。

## 测试

### 后端单元测试

- 分页同步首次 `NoConnection` 后重连，并从 checkpoint 完成剩余页面。
- 第二次 `NoConnection` 向上抛出且不标记 metadata 成功。
- 鉴权错误不进入连接重试。
- 启动状态失败后收到外部同步成功信号，恢复运行最终进入 `settled`。
- 同时出现多个成功信号时只启动一次恢复运行。
- 普通模式过滤 debug，调试模式立即放开，到期后重新过滤。
- 20 MB 文件轮转命名与选择正确。
- 14 天保留和 200 MB 总容量清理正确，且不删除非应用日志。
- 限频记录包含正确的 `suppressedCount`。
- 诊断 API 的查询、开启、关闭和非法参数行为。

### 前端测试

- 设置页读取并展示调试模式状态。
- 开启、手动关闭和到期后的状态变化。
- 请求期间禁用开关，失败时恢复并提示。
- 安全说明和自动关闭时间可见。

### 验证命令

- `npm test`
- `npm run typecheck`
- `npm run build:client`

## 完成标准

- 模拟历史分页同步连接中断后能够自动重连并完成同步。
- 后续同步恢复时，顶部旧失败提示自动消失。
- 普通运行不再持久化逐邮件智能处理和常规队列噪声。
- 调试模式可在设置中开启，30 分钟自动关闭且无需重启。
- 日志具备 20 MB 轮转、14 天保留和 200 MB 总容量限制。
- 现有历史应用日志被精确删除，审计和业务数据不受影响。
