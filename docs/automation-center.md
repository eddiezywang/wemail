# 自动化中心与内置模板

WeMail 的“自动化”是一个本地工作流，不是某个 Provider 或 CLI 的别名。普通用户只需要理解五个阶段：

1. 触发：手动、定时、收到邮件，以及事件后的延时。
2. 数据：读取哪些邮箱、时间范围和邮件。
3. 分析：归纳、分类、提取或生成结构化结果。
4. 产出：消息、表格、图表或 HTML 报告。
5. 投递：Agent 对话、消息中心、桌面提醒或已连接 Bot。

Provider、Capability、模型、Cron、指纹和版本只出现在高级配置或技术诊断中。某个可选执行环境不可用时，只阻塞依赖它的阶段，不把整条用户意图描述成“执行失败”。

## 配置与确认

自然语言配置和表单配置共享同一份 `ExecutionPipelineDraft`：

1. Agent 解析意图并生成草稿。
2. 系统验证当前内置能力和连接状态。
3. 需要主观判断的产出（图表、HTML、摘要口径等）生成预览。
4. 用户用自然语言同意或提出修改；修改会使受影响的旧预览失效。
5. 所有必需评审完成后，系统展示触发、数据、处理、产出、投递和账号范围的最终摘要。
6. 用户精确确认后才创建或替换规则版本；创建草稿、试运行和模板预览都不会启用定时任务或执行外部投递。

旧版 V1 邮件规则仍可直接启停和试运行。涉及结构、处理或投递方式的修改会先升级为 V2 草稿，原规则在确认前保持不变。

## 内置模板

模板是不可执行的声明包，包含本地化描述、配置 Schema、安全 UI Schema、工作流蓝图、结果 Schema 和渲染器版本。模板不能包含脚本、Provider 名称、凭据或任意组件。系统内置模板受保护；个人模板使用独立目录和不可变版本。

模板升级不会静默改变现有规则。升级先生成语义差异和新预览，精确确认后创建新规则版本；旧版本仍可回滚。

### 邮箱速览

`subscription-daily-insight` 是独立的内置模板，默认每天 09:00 处理全部已连接邮箱：

- 只读取已冻结的 24 小时输入窗口；
- 按账号公平分页，保留扫描、入选、排除和截断统计；
- 优先使用 List-Id、List-Unsubscribe、Precedence、文件夹、回复和安全信号；
- 排除私信、业务往来、垃圾邮件、钓鱼邮件和已回复邮件；
- 对消息、活动、发件人、标准化主题和链接指纹去重分组；
- 最多展示四个重点来源，完整来源保留在运行详情；
- 空结果只保留运行历史，默认不发布消息；
- 退订等变更动作必须有可验证目标，并进入预览与确认流程。

## 账号范围与来源

规则范围可以是当前邮箱、指定邮箱或全部已连接邮箱。跨邮箱规则由本地 Profile 拥有，生成一条消息中心结果，不会在每个邮箱复制一条。每个来源都同时保存 `accountId` 和 `emailId`；打开来源时会使用对应账号。账号断开后，历史结果仍保留摘要，但来源显示为不可用，不会猜测或串号。

“全部已连接邮箱”只在每次新运行认领时解析账号列表。运行已经认领后，新增或移除账号不会改变该次冻结输入或重试内容。

## 运行、恢复与保留

运行详情先展示业务结果、覆盖范围、阶段和投递，再在折叠区展示模型、资源、版本和指纹。只有服务端判定输入、能力指纹、权限和副作用都安全时，界面才显示“重试此步”。投递重试可能重复发送，必须再次确认。

运行摘要长期保留；输入清单、步骤详情和结果数据默认保留 30 天。到期后，系统清除来源明细、结果正文、使用量和副作用细节，但保留规则、运行状态、时间、计数、哈希和明确的“已过期”状态。归档不会立即删除数据；永久删除是单独操作，并且存在消息、运行或动作引用时会被阻止。

## 故障排查

- “需设置”：模板依赖的账号、Bot 或本地能力尚未准备好。打开连接设置或调整投递方式。
- “某阶段被阻塞”：只处理该阶段给出的恢复操作；已成功的上游阶段不会重跑。
- “结果已过期”：运行摘要仍然有效，原始内容不会被重建。
- “渲染器不支持”：升级客户端；系统只显示安全元数据，不会把未知结果当 HTML 渲染。
- “账号已断开”：重新连接对应邮箱后发起新运行。历史重试仍使用原冻结清单，不自动换用其他邮件。
