# Secure local mail MCP

WeMail now includes an opt-in local MCP endpoint for supported desktop hosts. It is loopback-only, account-scoped, disabled by default, and uses one-time-display bearer tokens stored through WeMail's existing SecretStore boundary.

The public catalog supports mailbox/folder discovery, bounded sync status, envelope list/search, targeted message/thread reads, session-bound attachments, drafts, Todos, reversible read/star state, and authenticated external side effects. Sending and destructive/batch actions are prepared as approved and then committed with durable idempotency; they do not create a WeMail confirmation prompt.

The hardened v1 contract exposes sender and message flags on envelope list/search results, exposes sender, recipients, timestamps, and attachment ids on targeted reads, and exposes recipients plus byte-free attachment metadata on draft review. Every tool includes standard MCP risk annotations. Outbound bytes now enter through the session-scoped `upload_mail_attachment` tool; draft and send tools accept opaque upload references plus attachment ids already owned by an existing draft instead of inline Base64. Temporary uploads expire after 15 minutes and are bounded per session and process, while final attachment sets remain capped at 20 files and 25 MiB decoded in aggregate. The HTTP endpoint rejects bodies above 40 MiB and rejects non-loopback browser Origins while continuing to support native clients that omit Origin.

An emergency environment switch, `WEMAIL_MCP_EMERGENCY_DISABLE=1`, prevents MCP startup without deleting mailbox data.
