# 飞书与企业微信机器人

WeMail 通过内置的无窗口 Bot Core 连接飞书和企业微信。客户只需安装并启动 WeMail，不需要安装 LangBot、Qwen Code CLI 或另一个服务。关闭主窗口到系统托盘后连接继续运行；明确退出 WeMail 时连接停止。

## 运行结构

- Electron 主进程监督一个 `utilityProcess`，服务名为 `WeMail Bot Core`。
- Bot Core 内置并精确锁定以下 Qwen Code Channels 依赖：
  - `@qwen-code/channel-base@0.21.1`
  - `@qwen-code/channel-feishu@0.21.1`
  - `@qwen-code/channel-wecom@0.21.1`
- 飞书适配器使用 Lark 官方 Node SDK，企微适配器使用企业微信智能机器人官方 Node SDK。
- Qwen 只负责平台协议、长连接、重连和发送；消息进入 WeMail 后仍由 WeMail 的 Agent、会话、授权和确认体系处理。
- Bot Core 使用版本化 MessagePort 协议与 Electron 主进程通信，不监听公共端口，也不会创建窗口。

## 配置飞书

1. 打开 WeMail 的 **设置 → 连接 → 飞书**。
2. 进入[飞书开放平台](https://open.feishu.cn/app)，创建企业自建应用。
3. 启用机器人能力，配置需要的消息事件和权限；至少开通“发送、删除消息表情回复”（`im:message.reactions:write_only`），选择长连接接收事件，并发布可用版本。
4. 将 App ID 和 App Secret 填入 WeMail。Secret 保存后不会再次显示。
5. 保存后，WeMail 在后台启动连接。生成主人配对命令，并让主人在与该机器人的私聊中发送命令。
6. 配对成功后，WeMail 主动发送一次初始化消息；送达后状态才变成“已连接”。

群聊默认只有明确提及机器人时才会触发 Agent，并按群和发送者隔离会话。

## 配置企业微信

1. 打开 WeMail 的 **设置 → 连接 → 企业微信**。
2. 进入企业微信管理后台，创建智能机器人并启用长连接。
3. 将 Bot ID 和 Bot Secret 填入 WeMail。WeMail 使用官方 SDK 的默认长连接地址，无需额外配置。
4. 保存并连接后，通过私聊一次性命令完成主人配对。
5. 初始化消息成功送达后进入“已连接”状态。

## 主人、授权与自动化

每个平台机器人只有一个当前主人。主人身份由平台真实私聊消息验证，不允许手工粘贴用户 ID 直接认领。重新绑定会增加主人版本并保留历史记录；依赖旧主人版本的自动化规则必须重新确认。

WeMail 当前是单邮箱租户。主人通过一次性命令完成验证后，系统会自动把该平台身份绑定到当前已登录邮箱，不再要求第二次邮箱授权。企业微信已验证主人可以在私聊中创建和修改草稿；发送或定时发送必须先保存草稿并展示邮件预览，用户在下一轮自然语言确认后，系统按该快照执行，不再要求应用内二次确认。群聊、飞书、非主人身份及其他高风险邮件操作仍走 WeMail 原有确认机制。

自动化 `publishBotMessage` 使用稳定的机器人 Profile，严格区分飞书和企业微信。可选目标是：

- 当前已验证主人；
- 该机器人实际观察到并被标记为可用的私聊或群聊会话。

消息内容在入队前冻结。默认总计尝试三次，重试只发送既有投递，不重新执行规则匹配、处理器或 AI。

## 状态与检测

客户端立即展示上一次完成的 WeCLI、飞书和企业微信检测结果，然后每次应用启动只在后台静默检测一次。没有定时轮询、窗口聚焦检测或进入设置页自动检测。

左下角只显示上一次确认“已连接”的能力；未配置、异常、未知和检测中的条目只在完整连接设置中展示。普通“检测连接”不发送消息，“发送测试消息”是单独且明确的操作。

## 安全与恢复

- 平台 Secret 由 Electron `safeStorage` 加密；SQLite 只保存 secret reference。
- 明文凭据只通过 Bot Core 的私有 MessagePort 传递，不进入命令行、环境变量、日志、API 响应或崩溃信息。
- 配对码和确认引用只保存哈希，短时有效、一次性使用，并绑定平台、机器人、聊天和发送者范围。
- 企业微信主人私聊的发送/定时发送预授权仍校验当前 Profile、Bot、主人、邮箱归属和上一轮预览确认，并记录执行审计；重复、跨邮箱或未经预览的动作不会执行。
- 平台消息 ID 用于入站幂等；出站使用持久账本、租约和有界重试。
- Bot Core 崩溃或心跳超时后由 Electron 主进程按退避策略重启并重放启用配置。
- “断开连接”会停止对应适配器、禁用 Profile 和邮箱绑定，同时保留可诊断的历史状态。

## 当前限制

- MVP 每个平台最多配置一个机器人。
- 飞书会在通过绑定、发送者与群聊 @ 检查后，立即在用户原消息上添加原生 `OnIt` reaction，并在处理结束后移除；reaction 失败不会中断或重跑邮件任务。
- 企业微信智能机器人长连接协议当前没有按消息 ID 添加 reaction 的接口；WeMail 不会用独立表情消息冒充 reaction。
- 入站文本、图片和文件元数据可识别；不会任意下载暂不支持的附件。
- 出站以文本/Markdown 为主。
- 交互卡片、平台原生流式更新、语音和可信共享群会话留作后续版本。
