# 升级后启动提示数据库字段不存在

## 先给结论

如果 WeMail 在升级后无法进入主界面，并显示 `no such column: ...`，故障发生在本地数据库启动阶段，不是邮箱密码、IMAP 或普通网络问题。该提示只证明当前程序读取了本地数据库中不存在的字段；它提示版本与数据结构不兼容，但不能仅凭这一行断言数据库已损坏，也不能断言是哪一次迁移失败。

请不要删除本地数据、清理应用数据目录或反复卸载重装，这些操作可能破坏恢复现场，也不会自动补齐缺失的数据结构。

启动恢复窗口会显示“重启 WeMail / 复制诊断编号 / 退出”。请先点击“复制诊断编号”，再保留完整错误截图；重启一次仍失败后，不要继续反复重启。

客服应请用户保留当前现场，收集：

1. 当前 WeMail 版本和升级前版本；
2. 完整的用户可见错误文字或截图；
3. 首次失败的时间，以及是否每次启动都复现；
4. 启动恢复窗口中的诊断编号；
5. 如果故障是间歇性的、稍后能够进入主界面，再通过“设置 → 高级设置 → 诊断 → 导出诊断包”取得诊断文件；持续无法启动时没有这个入口，不要要求用户寻找它。

## 分流和闭环

- 只有页面意外停止、窗口仍存在：按页面恢复问题处理，不要套用本条数据库结论；
- 明确出现 `no such column` 且无法进入主界面：保留现场后重启一次，仍失败就立即建立 WM-01 启动阻断案例；
- 同一版本使用新数据可以启动，只能作为“与既有数据结构有关”的支持证据，不能指导用户创建新数据目录继续使用。

案例写明优先级“启动阻断”，记录预期、实际错误、升级前后版本、首次发生时间、诊断编号、一次重启结果和临时处理。内部建单成功后只能依据工具真实回执回复“已记录”，普通回复不展示编号；仅在需要转私聊传递材料时展示一个 `case_id`。工具失败时应明确“暂未记录成功”。

不要指导用户手工修改数据库、迁移文件、删除数据或创建新数据目录来绕过。不要收集邮箱密码、授权码、API Key、数据库原文件或邮件正文；诊断包仅通过产品内置导出入口取得，分享前应核对其中不含业务正文。
