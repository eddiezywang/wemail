# 邮件摘要与智能中心使用和排查

## 当前能力

打开一封已接收邮件后，邮件详情中的“智能摘要”可以展示摘要要点、识别出的待办和紧急程度。摘要任务依赖已存入 WeMail 的正文和可用的 AI 模型；智能中心把正文未就绪显示为“邮件正文尚未同步完成”，此时应先处理正文同步，不能把反复重试摘要当成修复。

“智能中心”用于集中查看当前邮箱账户的智能处理状态，包括失败、未生成、内容无效、排队中、生成中、已完成和已跳过。这里可以按全部邮件或指定文件夹筛选，查看单封任务详情，并对可重试任务重新入队。

页面顶部的“智能处理吞吐监控”会分别展示总邮件、已完成、排队中、生成中、失败和可重试数量，并可切换 Token/调用数、按分钟/按小时查看趋势及任务类型分布。按分钟支持近 1、2、6 小时，按小时支持近 1、2、7 天。这些数据用于判断任务是否在推进，不等同于模型服务商最终账单。

智能中心不是“每日简报”“每周简报”或历史简报列表。用户询问定时汇总或自动推送时，应转到 WM-12 自动化；询问图表、趋势或洞察报告时，应转到 WM-13。

## 真实入口

- 单封摘要：打开邮件，在正文后的智能信息区域查看“智能摘要”。摘要失败且界面提供“重试”时，可直接重试；成功时可核对摘要要点、待办和紧急程度。
- 批量诊断：在邮件列表顶部点击“打开智能中心”。当前设置对话框没有单独的“摘要中心”按钮，不要指导用户在设置中寻找该入口。
- 模型状态：打开“设置 → AI 模型”，检查服务是否“已就绪”。摘要模型留空时继承默认模型。
- 并发设置：进入“设置 → 高级设置 → 性能”查看“AI 任务并发数”。它影响摘要、智能标签和回复判断等后台任务，不是右侧助手的同时聊天数。

## 常见问题

### 为什么摘要一直没有生成？

先看智能中心中的具体状态：

1. 显示“邮件正文尚未同步完成”：先等待该邮件正文同步；正文长期为空属于 WM-03 邮件同步问题，不能只靠重复生成摘要解决。
2. 显示“模型未配置”或模型不可达：到“设置 → AI 模型”完成配置或恢复连接。返回智能中心查看任务状态；仍为失败、未生成或无效时，再重试对应任务。
3. 显示 401/403：检查当前模型凭据和权限；不要让用户在聊天中发送 API Key。
4. 显示 429、超时或 5xx：可以稍后重试；如果同一模型持续影响多封邮件，应记录故障。
5. 显示“邮件内容为空”：先确认正文是否在 WeMail 中可见，不要把它误判为模型质量问题。
6. 显示“内容无效”或模型输出不完整：可重新生成；持续复现时记录所用模型、邮件语言和任务状态。

### 为什么任务长期排队或处理很慢？

先看吞吐监控，而不是连续点击重试：

1. “排队中”很多且调用趋势持续增长，说明任务仍在处理，可观察一段时间；
2. 排队持续增加而调用数长期为零，检查模型状态及具体失败提示；
3. 调用数上升但 429 或可重试数量同步增加，通常不应继续调高并发；
4. 只有在模型服务商允许更高并发且当前没有限流时，才到“设置 → 高级设置 → 性能”逐级提高并发。

“AI 任务并发数”当前范围为 1–16，默认 2。提高并发可能加快批量回填，也可能触发模型服务商限流并降低实际吞吐；不要把 16 当成推荐值。

### 摘要不准确或遗漏重点怎么办？

先核对原邮件正文是否已经完整显示，再区分两类问题：原文缺失属于 WM-03；原文完整但摘要事实错误、遗漏关键截止时间或凭空增加承诺，属于 WM-06 质量问题。不要要求用户粘贴整封敏感邮件；优先记录脱敏后的主题、时间、错误摘要片段及它与原文的差异。

## 临时绕过与建单条件

少量邮件可在正文完整后对单封任务重试或勾选后批量重试。顶部“重试”会打开“重新入队智能处理”对话框，必须明确选择范围：

- “从没跑过（最新优先）”：只选从未生成过智能摘要的邮件；
- “失败的任务”：只选已经尝试但失败的邮件；
- “全部”：包含失败、未生成和空/无效任务。

入队数量默认 500，单次允许 1–2000，并按收信时间最新优先选取。界面会预览实际入队数量；“无可入队”表示当前范围没有符合条件的任务。不要在状态仍为排队中或生成中时连续重试，也不要为了处理少量失败邮件直接选择“全部”。重试只是恢复手段，不能替代以下问题的建单：

- 正文完整、模型可用，但同一封邮件多次生成失败或结果无效；
- 多封任务长时间停在排队中或生成中；
- 摘要稳定地捏造事实、日期、附件、决定或承诺；
- 明确范围重新入队后仍有任务入队失败，或任务状态与邮件详情不一致；
- 吞吐监控长期显示队列不推进、调用为零，且模型已确认可用；
- 吞吐数据加载失败但单封任务仍在运行时，先区分“监控失败”和“处理失败”，不要把两者合并建单。

建单时归入 WM-06，记录版本、任务状态、错误提示、模型、复现时间和预期/实际结果。内部建单成功后可以说“已记录”，普通回复不展示编号；仅在需要转私聊传递材料时展示一个 `case_id`。失败则明确“暂未记录成功”。不得收集邮箱密码、API Key、完整敏感正文或附件原件。

## 推荐回复

> 这不是正常完成状态。请先在邮件列表顶部打开“智能中心”，点开这封邮件的任务，告诉我当前显示的是“正文尚未同步、模型未配置、排队中、失败”还是“无效”。不同状态处理方式不同；确认后我再给你最短处理步骤。请不要发送 API Key 或完整邮件正文。
