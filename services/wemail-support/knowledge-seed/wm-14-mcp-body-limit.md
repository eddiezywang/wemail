# MCP 邮件正文长度与高级限制设置

## 当前正式产品结论

当前正式版 WeMail 已经支持用户配置 MCP 正文长度，不是待开发 feature：

- Windows 桌面版“设置 → MCP → 诊断与高级连接信息”确定包含“默认正文长度”和“正文长度上限”；
- “正文长度上限”默认是 20000，允许配置到 1000000；
- 当前 `get_mail_message` 和 `get_mail_thread` 的公开工具 schema 中，`maxBodyCharacters.maximum` 是 1000000；
- 实际返回长度取客户端请求值和应用内“正文长度上限”中较小的一个。

因此，用户贴出的 `maximum: 20000` 是旧版工具定义，不是当前 WeMail 的产品上限。客服应直接说明当前产品已经支持配置，并引导保存设置后断开、重新连接 MCP 客户端，使客户端重新执行 `tools/list` 获取当前 schema。不要让用户检查产品有没有入口，不要归类为 feature，也不要讨论研发修改 schema 或服务端逻辑。

## 已具备高级设置的版本中如何理解数值

新版 WeMail 的 `get_mail_message`（部分客户端显示为 `mcp_wemail_mail_mcp_get_mail_message`）同时存在三个不同概念：

- “默认正文长度”为 6000：客户端没有传 `maxBodyCharacters` 时，每封邮件默认返回的正文长度；
- “正文长度上限”默认为 20000：客户端当前允许请求的每封邮件正文最大长度；
- 程序允许配置的绝对上限为 1000000：在新版设置中可以把“正文长度上限”调高，但不能超过该值。

因此，在界面已经提供高级限制的版本中，20000 是默认配置，不是不可修改的硬上限。实际返回长度取客户端请求值和当前“正文长度上限”中较小的一个。返回结果的 `truncated: true` 表示正文按当前长度被截断，不等于邮件没有同步完整。

## 怎么调整

进入“设置 → MCP”，展开“诊断与高级连接信息”，修改：

1. “正文长度上限”：提高客户端单封邮件可请求的最大长度；
2. 如希望客户端不传参数时也返回更多内容，同时调整“默认正文长度”；
3. 保证“默认正文长度”不高于“正文长度上限”，保存后再让 MCP 客户端重新读取。

提高上限会增加单次响应体、内存占用和工具执行时间。只调整到业务确实需要的范围，不要直接把所有限制都设到最大。若调用仍超时，可结合“MCP → 诊断与高级连接信息”中的“工具超时”判断，但不得通过关闭鉴权、回环监听、请求体、速率或并发安全边界来规避。

## 旧工具定义的处理

客户端仍显示 1–20000 时，先在 WeMail 保存所需的“正文长度上限”，然后断开并重新连接 MCP 客户端或刷新工具定义。刷新后的当前 schema 应显示 `maximum: 1000000`。如果重连后仍显示 20000，再建立 WM-14 案例，记录 WeMail 版本、客户端名称和刷新方式；不要让用户发送完整 MCP JSON、Authorization 或连接凭据。

## 仍然存在的能力边界

`get_mail_message` 目前没有正文偏移量或续读游标；用相同参数反复调用只会得到相同前缀。以下情况才应建立 WM-14 案例：

- 已确认使用包含高级限制设置的版本，但保存值后读取仍固定停在旧上限；
- 请求值不高于当前设置，仍被异常截断或工具定义没有刷新；
- 邮件正文超过 1000000，或业务明确需要分段续读；
- 调高到合理长度后持续超时、响应失败或结果中的截断信息与实际返回不一致。

建单写明 WeMail 完整版本、调用工具、请求长度、当前“默认正文长度”和“正文长度上限”、`truncated` 值、实际邮件大致字符数、客户端类型及预期结果。不要把完整长邮件、MCP 配置或凭据放进案例。只有工具成功返回真实 `case_id` 和 `todo_id` 后才能说“已记录”；普通的设置指导不需要伪造产品待办。

## 推荐回复

> 可以。当前正式版已支持在“设置 → MCP → 诊断与高级连接信息”调整“正文长度上限”，默认是 20000，最高可设为 1000000。你看到的 `maximum: 20000` 是 MCP 客户端保留的旧工具定义；保存新上限后断开并重新连接 MCP 客户端，让它重新获取工具定义即可。
