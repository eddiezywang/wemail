# WeMail 客服领域模块目录

- WM-01 安装、升级与桌面运行
- WM-02 账户、认证与邮箱连接
- WM-03 邮件同步与邮箱管理
- WM-04 写信、回复与发送
- WM-05 通讯录与收件人
- WM-06 邮件摘要与智能处理中心
- WM-07 分类、智能标签与学习
- WM-08 邮件待办
- WM-09 邮件搜索、问答与内容理解
- WM-10 AI 写作、智能回复与个性化
- WM-11 个人助理、个性化偏好与学习数据
- WM-12 自动化
- WM-13 洞察报告与业务场景
- WM-14 Skill Center、MCP 与 WeCLI
- WM-15 外部连接与 Bot 渠道
- WM-16 AI 模型、免费额度、推理性能与使用量
- WM-17 设置、通知、数据隐私与诊断

跨领域问题只选择一个最主要的责任模块，并把其他领域登记为相关模块，避免重复建单。主模块按“最先出现异常、需要谁负责修复”选择，不按用户最后提到的菜单选择。例如：自动化处理完成但企微投递失败，测试消息也失败时主模块是 WM-15、WM-12 为相关模块；Bot 测试正常而自动化没有发起投递时主模块是 WM-12。

## 用户可见入口映射

- 主导航：收件箱与邮件夹（WM-03/09）、已延后（WM-03）、待办（WM-08）、应用消息（WM-17）、自动化（WM-12）、通讯录（WM-05）、智能标签（WM-07）。邮件列表顶部另有“智能中心”（WM-06），用于查看智能处理任务状态和重试，不是应用消息或定时简报历史。
- 右侧助手：当前邮件问答、当前邮箱候选搜索与内容理解（WM-09），以及个人助理和待确认任务（WM-11）。“搜索整个邮箱”用标题、发件人和时间等条件找候选邮件，不等于对全部历史正文进行无限制全文检索。学习工作空间是独立的只读页面，不属于右侧助手。
- 设置一级项：账户（WM-02）、个性化（WM-10/11）、AI 模型（WM-16）、MCP（WM-14）、连接（WM-15）、Skill Center（WM-14）、关于和高级设置（WM-01/16/17）。“AI 模型”的高级设置包含推理强度；“高级设置 → 性能”包含后台 AI 任务并发；“高级设置 → 签名”管理当前邮箱默认签名。“个性化”包含回答语言/风格、待办规则和 Agent 学到的偏好；当前设置没有“智能中心”、“学习中心”或“写作风格”一级按钮。写作风格从 AI 写作条的“管理写作风格”进入。
- 其他能力：洞察报告从邮件详情智能区域或右侧助手发起，成功产物进入“应用消息”（WM-13）。学习工作空间已有只读页面，但当前主导航和设置中没有固定可见入口；对普通用户应优先引导“设置 → 个性化 → Agent 学到的偏好”（WM-11），不得虚构“学习中心”菜单。

用户询问“在哪里”或“怎么用”时，回答必须使用当前界面真实显示的名称，不得只回复模块编号或内部路由。

## 快速分流

1. 先识别用户正在使用的入口和对象：WeMail 邮件/助手、MCP 客户端、WeMail 外部 Bot，还是 Hermes 客服机器人。
2. 再识别阶段：入口不可见、配置失败、运行失败、结果错误、投递失败或隐私疑虑。相邻模块不能仅凭表象互相替代，例如“群里没消息”不一定是自动化失败。
3. 最后选择主模块；只在确有依赖关系时添加相关模块。一个用户现象只建一个案例，后续由管理员调整模块，不重复制造待办。

内部建单成功后可以说“已记录”，但普通咨询和同一问题后续不展示编号；只有确实需要从群聊转私聊传递材料时才展示一个用于续接的 `case_id`。“已记录”不等于已修复或已排期。目录本身只负责分流，具体能力、数值、排查和安全证据必须回到对应已发布专题文档核实。

分流时只记录最小且脱敏的现象、预期、实际、入口、版本和时间。不得把密码、Key、Token、Bot Secret、配对命令、完整邮件正文、诊断包原文或源码放进案例来“帮助判模块”。需要诊断包才能区分根因时优先建议一对一支持会话；用户直接发到群聊时不拦截，由受限工具读取后仅在群里回复二次脱敏的最小结论。只有确实要从群聊转入私聊传递材料时才创建并展示一个交接 `case_id`，同一问题不重复创建。
