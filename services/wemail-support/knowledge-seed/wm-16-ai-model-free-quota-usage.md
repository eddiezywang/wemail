# AI 模型、免费额度、自有 API Key 与用量排查

## 配置自己的模型

免费额度已下线。请进入“设置 → AI 模型”，填写自己的端点、API Key 和默认模型并保存。

API Key 是只写配置：WeMail 只显示是否“已配置”，不会把已保存的密钥重新回显。再次打开页面时密钥框为空属于正常行为；不输入新密钥直接保存会保留原有密钥。客服不得要求用户把 Key 发到聊天或案例中。

WeMail 会根据填写的端点和密钥探测 OpenAI 兼容或 Anthropic 协议。可以分别为摘要、草稿和 Agent 指定模型；未单独设置时使用默认模型。只应填写用户信任的模型服务端点：使用 AI 功能时，相应输入会发送给当前选择的模型服务，不能把“API Key 保存在本机”理解成 AI 内容完全不离开本机。

端点须为 HTTP(S) 地址，不能包含用户名、密码、查询参数或片段；密钥应填写在 API Key 字段。模型列表探测和生成请求均不跟随重定向，如果服务要求跳转，请直接填写最终服务地址。

连接探测失败时，设置仍会保存，页面会提示检查端点、密钥和网络；保存成功不代表模型已验证可用。如果提示运行时重载未完成，设置已保存，请重启应用后再验证 AI 功能。模型列表探测也不等于测试了具体模型的实际生成能力。

## 自定义模型不可用

依次检查：

1. 页面是否显示模型已配置且运行状态可达；
2. 默认模型是否已填写；保存时默认模型不能为空；
3. 端点是否与所用服务兼容，模型探测能否列出模型；
4. 401/403 通常检查密钥权限或有效性，429 检查服务限流或余额，网络/超时和 5xx 可稍后重试；
5. 仅摘要、草稿或 Agent 中一个功能失败时，核对该能力是否配置了不同模型，不要笼统判定整个 AI 服务不可用。

## 推理强度怎么选

进入“设置 → AI 模型”，展开“高级设置”，可以调整“推理强度”：

- “自动（推荐）”：由 WeMail 根据模型家族采用兼容策略；
- “不发送”：请求中不携带 `reasoning_effort`，适合明确不接受该参数的 OpenAI 兼容服务；
- “关闭（none）”：明确请求关闭推理；它和“不发送”不是一回事；
- low、medium、high、xhigh、max：手动覆盖自动策略，但服务商和具体模型未必支持全部档位。

若保存后请求返回 HTTP 400，并明确提示 `reasoning_effort` 不支持或取值无效，先切换为“不发送”再验证，不要误判为 API Key 错误。部分兼容网关不接受 `none`、但声明最低支持 `low` 时，WeMail 会进行一次有界兼容回退；这不等于所有网关或模型都支持 `none`。用户没有说明版本时按当前正式版存在该设置回答；只有用户明确提供旧版本或旧界面证据时，才引导检查更新，不要修改内部数据库。

## AI 任务并发怎么调

进入“设置 → 高级设置 → 性能”可以调整“AI 任务并发数”。当前范围为 1–16，默认 2，影响摘要、智能标签、回复判断等后台智能任务，不是右侧助手允许同时进行的聊天数。

提高并发可能加快首次登录后的批量智能回填，但同时增加模型请求速率。出现 429、超时或失败数量随并发上升时，应降低并发或等待服务商限流恢复，而不是继续调到 16。建议每次只提高一级，并结合智能中心的排队、生成中、失败、可重试和吞吐趋势验证效果。

## AI 用量在哪里看

进入“设置 → 账户”中的“AI 用量”。可查看近一月、近三月、近半年和近一年，并按摘要、待办、AI 聊天、翻译、撰写、自动化、标签/其他分类查看输入与输出 token、调用次数和模型维度。

用量记录按当前邮箱账户写入本机数据库，并随 AI 调用更新。页面为空只表示当前账户和所选时间范围内没有已记录用量；先确认账户、扩大时间范围并点击“刷新”。不能据此推断云端账单为零，WeMail 的 token 统计也不等同于第三方模型服务商最终计费账单。

## 何时建单

满足任一项应建单：有效自定义配置保存后状态未更新；模型探测成功但所有 AI 功能稳定失败；某一能力始终使用错误模型；选择“不发送”后仍发送不兼容的 `reasoning_effort`；支持的推理档位稳定被错误改写；保存并发后界面与实际值不一致；合理并发下任务长期不消费；实际有本机 AI 调用但刷新和扩大时间范围后用量仍为空；同一调用被明显重复计数。

案例归 WM-16。建议收集：WeMail 版本、失败的能力、模型名称、端点域名（不含路径、查询参数和凭据）、HTTP 状态类别、发生时间、页面状态、用量时间范围和预期调用次数。不得收集 API Key、Authorization 头、完整请求、模型服务原始响应或邮件/AI 输入输出内容。

写清预期、实际、失败范围和临时处理。内部建单成功后可以说“已记录”，普通回复不展示编号；仅在需要转私聊传递材料时展示一个 `case_id`。工具失败只能说“暂未记录成功”。若 Key 已发到聊天或案例，先撤回并到模型服务商处轮换。

## 标准答法

用户问“免费套餐能不能用自己的 API Key”时，先回答：

> 免费额度已下线。请到“设置 → AI 模型”填写端点、API Key 和默认模型后保存；不要把 Key 发到聊天里。

用户问“模型报 reasoning_effort 不支持”时，先回答：

> 到“设置 → AI 模型 → 高级设置”，把“推理强度”改为“不发送”后再试。“不发送”表示请求中不携带这个参数；它和“关闭（none）”不同。这个错误通常是模型服务的参数兼容问题，不代表 API Key 一定无效。

用户问“摘要回填慢，能不能把并发调满”时，先回答：

> 可以在“设置 → 高级设置 → 性能”逐级调整“AI 任务并发数”，范围是 1–16、默认 2，但不建议直接调满。请先看智能中心的吞吐和失败状态；如果已经出现 429 或超时，应降低并发，而不是继续提高。
