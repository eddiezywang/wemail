# WeMail 企微支持助手初版架构

企微消息由 Hermes Gateway 接收。模型负责理解意图和组织语言，`wemail-support-runtime` 插件负责不可绕过的身份、权限、数据与发布约束。

## 两个平面

- 服务平面：普通用户搜索已发布知识、读取原文、反馈问题、查询自己的案例。
- 控制平面：管理员按模块处理案例和支持待办，提交、审核、发布或回滚知识，超级管理员维护管理员名单。

知识检索采用 Agentic Search：Markdown 原文存储在本机，运行时生成 `index.md` 文档地图；Agent 先检索，再读取完整原文。不把源码目录暴露为搜索语料。

`product-baseline.json` 是客服所说“当前正式版”的唯一基线。开发分支中尚未进入该基线的代码不能当作已发布能力。知识部署用内容哈希追踪仓库种子；仓库更新只能覆盖仍等于上次种子的运行文档，不能绕过企微中的审核发布覆盖人工维护版本。

## 数据流

1. Hermes 从企微取得可信 user ID、会话和群聊/单聊上下文。
2. Skill 强制产品回答先检索公开知识。
3. 无法解决或需要跟进时创建支持案例。
4. 数据库事务同时建立支持待办，随后向负责模块的管理员通知入口发送消息。
5. 管理员在企微更新案例、指派待办或提交知识草稿。
6. 草稿经审核后进入公开知识目录，生成版本和新索引；全部变更写入审计日志。

## 本机运行数据

运行数据位于 `%LOCALAPPDATA%\hermes\wemail-support`：SQLite 案例库、管理员配置、发布知识、草稿、归档和索引。真实企微 ID、案例、审计记录与未发布资料不进入 Git。

## 安全约束

- 插件入口只接受有用户 ID 的企微会话；权限由网关 user ID 后端校验，不信任提示词传入的角色，也不跨平台复用同名 ID。
- 普通用户只能读取公开知识和自己的案例。
- 模块管理员只能管理授权模块；最后一个超级管理员不能被删除。
- 用户语料与源码语料物理分离；搜索工具只返回批准发布的 Markdown。
- 案例输入和知识草稿对可识别的凭据模式做脱敏；自由文本中仍可能残留敏感信息，提交和分享前必须检查。
- 发布采用草稿、审核、版本、原子替换和审计，不允许聊天直接覆盖生产知识。
