# 邮件数据分析

负责“从数据中发现什么”，不负责最终页面样式。输入是 `data-selection`、`dataset` 或 `analysis-recipe`，输出为 `analysis-result`。

## 执行原则

1. 多封邮件必须先逐封提取，再按业务语义聚合；不得把缺失邮件静默排除。
2. 优先使用宿主侧确定性分析：字段画像、分位数、相关性、排名、贡献率和异常检测不调用模型。只有主题归类、原因解释等无法由结构化字段完成的任务才使用有界模型任务。
3. 区分业务时间与邮件接收时间。存在业务时间时优先使用业务时间；合成接收时间必须在结果中标注。
4. 指标必须标记为可加、平均、比例、时长或普通数值。比例使用分子/分母重新计算，不平均百分比；p95 必须保留单位。
5. 对每个适用视角执行覆盖检查：总体、趋势、构成、分类比较、分布、指标关系、交叉矩阵、层级、前后变化和异常。
6. “完整”表示覆盖所有适用关系，不表示穷举字段笛卡尔积。重复、低信息量或证据不足的视角必须降权或标记不适用。
7. 每条发现包含真实字段、聚合方式、来源邮件、事实/推断标记和证据强度；数据不足时明确返回不可判断。
8. 有可靠时间字段时，可确定性派生星期、月份和互斥时段；必须记录来源字段、转换规则和时区，不生成不可追溯的模型猜测字段。

## 输出契约

`analysis-result` 至少包含：

- `dimensions`：时间、时间窗口、分类、状态及基数。
- `measures`：语义、聚合方式、有效样本、最小值、最大值、中位数和 p95。
- `findings`：按信息增益排序的结论与证据字段。
- `intents`：独立于图表的分析关系，例如趋势、排名、占比、分布或相关性。
- `views`：由宿主图表选择器从 `intents` 确定性映射的精简图表规格、选择理由和得分，不含 ECharts option。
- `coverage`：每个分析视角是已覆盖、数据不足或不适用。

图表数量增加不得线性增加模型 token；默认由宿主侧分析结果直接生成图表规格。
