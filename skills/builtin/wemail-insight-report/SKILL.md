# WeMail 洞察报告

输入优先使用 `wemail-data-analysis` 产出的 `analysis-result`；也可接受已规范化的数据集或已定义的数据选择。最终输出可追溯的 HTML 洞察报告。不要直接编写 HTML、CSS、JavaScript 或图表库配置；只向 `publish_design_artifact` 提交数据、分析绑定和精简图表规格，由可信渲染器负责页面、图表、转义、来源和存储。

## 工作流

1. 没有数据集时，先完成邮件范围确认、逐封表格提取和必要聚合；多封邮件只允许最终汇总数据集进入报告。
2. 校验字段、单位、缺失值、异常值和来源。用户指定的分类、时间窗口、状态或必需值都是验收条件，缺失时停止发布并说明缺失项。
3. 将指标、维度和结论绑定到真实字段。占比明确分子与分母，p95 明确字段与单位；事实、推断和建议必须区分。
4. 优先使用宿主已从分析关系映射出的 `views`；只有用户明确指定图表时才覆盖。每张图只表达一个独立结论，标题写判断，不写图型名。
5. 调用 `publish_design_artifact` 生成报告。成功必须以返回的产物和应用消息标识为准；失败时不得用代码块或文字报告冒充成品。
6. 修改已有报告时传入 `reportId`，生成下一不可变版本。自然语言评审分为接受、拒绝、修订或不明确；不明确时不得默认接受。

## 图表选择

- 少量分类比较使用 `bar`，分类较多时使用 `bar` 或 `table`。
- 多时间点使用 `line` 或 `area`；单一快照不得生成趋势结论。
- 100% 构成使用 `waffle`，分类堆叠构成使用 `stacked-bar`。
- 两时点比较使用 `dumbbell`，二维关系使用 `scatter`，分类矩阵使用 `heatmap`。
- 连续数值分布使用 `histogram`；需要比较多组中位数、四分位区间和离群值时使用 `boxplot`。
- 两层非负权重层级使用 `treemap`；父值必须等于子值之和，叶子过多时合并长尾或改用表格。
- 含正负值的分类数据使用 `diverging-bar`，单指标总计使用 `counter`。
- 禁止断轴、3D、发光、渐变和无数据意义的装饰交互。

图表规格只包含 `{family, x, y, y2?, splitBy?, agg?, where?, top?, title?}`。所有字段必须存在于数据集；同一实体在整份报告中保持同色。默认报告优先使用宿主生成的多视角 `views`，不要为了减少输出字数主动删除有效图表。

## 设计系统

一份报告只使用一个颜色系统：

- 默认 `auto`。时间、进度、热力或有序排名使用 `porcelain` 青瓷蓝单色阶。
- 少量无序分类可使用 `palm`；只突出一个重点时可使用 `wire`；映射不明确或高密度时使用 `mono`。
- 用户明确提供品牌色时才使用 `custom:#RRGGBB,...`，并保证正文对比度至少 4.5:1、大字至少 3:1。
- 非单色系统中的细线宽度提高至 1.8 倍，半透明标记不低于 0.85；状态色优先于设计色。

不得在同一 HTML 中混用颜色系统，也不得单独给某一张图换色。

## 多封邮件报告

1. 按发件人、稳定主题片段和时间范围关联同类邮件，不把当前邮件当作滚动窗口的隐式兜底。
2. 每封邮件独立解析，再按业务语义选择时间粒度、分组字段及 `sum`、`average`、`min`、`max` 或 `latest`。
3. 保留用户要求的全部维度；时间窗口是比较轴，不替代分类维度。重叠窗口不得堆叠相加。
4. 只有最终汇总数据集可以发布；报告保留汇总行、聚合说明和轻量来源元数据，不保留正文或原始表格。
5. 有可靠时间字段时以折线图作为主视图并保留关键分类系列；只有一个快照时改用比较图或明细表。

通用服务监控指标参考 [监控场景](references/monitoring.md)。报告评审规则参考 [评审约定](references/review.md)。
