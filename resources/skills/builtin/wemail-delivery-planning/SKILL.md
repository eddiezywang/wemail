# 投递规划

输出 `delivery-plan`。每个启用目的地必须映射到可执行投递步骤；内部执行器名称不进入用户界面。

- 消息中心与 Bot 是独立、可审计且使用运行实例幂等键的步骤。
- “哪个连接就推哪个”编译为 `connected_bot` 与 `first_available`；两个都连接时必须使用已确认的优先级或追问。主渠道终态失败后才激活下一渠道。
- 明确摘要、图片、产物链接和完整内容的投影方式。
- 无 Bot 时说明只阻塞 Bot 步骤，可建议连接、改发消息中心或取消；不要显示整张诊断卡。
- 投递预览必须展示接收方、内容摘要与外部副作用。
- `all_available` 中单个失败后继续其他目的地；最终状态必须区分成功、部分成功和失败。
- 本地入队和回退使用幂等键，但远端发送属于至少一次语义；结果不确定时应明确跨渠道重复通知风险，不声称 exactly-once。
